# Hand-written stylesheet

## Goal

The browser client's appearance is generated by Tailwind and assembled from
vendored shadcn components. Both go. Replace them with one hand-written
stylesheet and the platform's own controls, so appearance lives in CSS that uses
inheritance, custom properties and cascade layers, and a control's markup says
what it is rather than what it looks like.

This task changes the toolchain and the styling of individual controls. It does
not change the information architecture, the arrangement of any region, or any
accessible name. The shell's layout, drawer, registration dialog and pinned
composer belong to the shell visual design task that follows.

`eng/mockups/shell.html` holds the settled stylesheet. Its `tokens`, `base` and
`controls` layers are this task's `client/src/styles.css`; its `layout`,
`sidebar`, `conversation` and `settings` layers belong to the next one.

## Related code

- `client/package.json` — `build` runs the Tailwind CLI before `bun build`, and
  `check` runs `build`. Both lose the CLI step; `styles.css` becomes a static
  asset the host already serves.
- `client/src/styles.css`, `client/public/styles.css`, `client/.gitignore` — The
  generated stylesheet becomes a checked-in one again.
- `client/components.json`, `client/src/components/ui/` — Deleted.
- `client/tsconfig.json` — The `@/*` path mapping exists only for the vendored
  components' imports.
- The nine modules under `client/src/components/` that import `@/components/ui`,
  listed by `grep -rn '@/components/ui' client/src`.
- `client/e2e/smoke.spec.ts:1153` — `chooseMode` drives the Radix combobox. Line
  515 and its neighbours click `Details` by text because Radix renders it as a
  button whose name the helper does not assert.

## Decisions

Colours are declared once with `light-dark()` rather than as a light block plus
a `prefers-color-scheme` block that repeats every name.
`color-scheme: light
dark` on `:root` is what makes that work, and it also gives
form controls and scrollbars the right rendering for free.

Every measurement that two regions have to agree on is a token: `--bar-height`,
`--control-height`, `--sidebar-width`. A value written twice in two files is the
defect this task exists to remove.

The stylesheet is organised with `@layer`, so a later rule cannot win by
accident and the shell styling task can add its layers without re-specifying
anything here.

Radix `Select` goes back to a native `<select>`, styled with `appearance: none`,
padding and a background chevron. The list itself stays the platform's, which is
what a phone wants. This restores `selectOption` and `toHaveValue` in the
end-to-end suite.

Radix `Collapsible` is replaced by one local `Disclosure` component — a
`<button aria-expanded>` and conditionally rendered content — rather than by
`<details>`/`<summary>`. `<details>` would be less code, but its summary is not
reliably a button across engines, and the suite already resolves every
disclosure by button name. A disclosure is the only behaviour worth keeping a
component for; `Button`, `Input`, `Label` and `Textarea` become the plain
elements they always wrapped.

The add-workspace dialog and the navigation drawer are not built here. When they
are, `<dialog>` and its `showModal()` supply the modal behaviour Radix was
carrying, so removing Radix does not create a gap to fill later.

`lucide-react` goes with the rest. Icons become inline SVG sized in `em`, as in
the mockup.

## Test plan

- `chooseMode` returns to `getByLabel("Mode").selectOption(...)` with a
  `toHaveValue` assertion. The elicitation `combobox` assertions at lines 459
  and 462 already drive a native select and must keep passing untouched.
- The disclosure clicks at lines 515, 522 and 543 become
  `getByRole("button", { name: "Details" })`, which is what the `Disclosure`
  renders. Every other `getByRole("button")` and `getByLabel` in the suite must
  resolve without edits; one that does not means a name moved, which is a defect
  rather than a test to update.
- `bun run check` no longer compiles CSS, so a broken stylesheet no longer fails
  the check. The Playwright suite is what proves the surface still works.

## Implementation plan

- Write `client/src/styles.css` from the mockup's `tokens`, `base` and
  `controls` layers, declare the full layer order including the layers the shell
  task will fill, and check it in as `client/public/styles.css`'s replacement.
  Remove the generated-file entry from `client/.gitignore`.
- Drop the Tailwind CLI from `build`, and drop `build` from `check`.
- Remove `tailwindcss`, `@tailwindcss/cli`, `class-variance-authority`, `cn`,
  `lucide-react`, `radix-ui`, `shadcn` and `tw-animate-css` from
  `client/package.json`.
- Delete `client/components.json`, `client/src/components/ui/`, and the `@/*`
  path mapping from `client/tsconfig.json`.
- Add `client/src/components/disclosure.tsx`.
- Port the nine components to plain elements, the `Disclosure`, inline SVG, and
  the stylesheet's class names, keeping every accessible name and every region.
- Update `chooseMode` and the three `Details` clicks in
  `client/e2e/smoke.spec.ts`.
