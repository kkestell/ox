# Subagents within one prompt run

## Goal

Let Ox delegate work to concurrent subagents while continuing to use its own
tools. Each subagent receives an assigned task and captured workspace
instructions, uses the same turn loop, and saves its conversation in a child
session. Its accepted final answer is forwarded automatically. Follow-up work
continues that conversation in another turn.

Subagents belong to one prompt run. They share the active session's background
commands, whose lifetime remains independent of prompt cancellation.

Follow `eng/architecture.md`, `eng/code-style.md`, `eng/glossary.md`, and
`eng/testing.md` for existing boundaries, naming, and validation.

## Related code

- `src/acp/prompt.rs`: Shared model loop, batch saving, hooks, permissions,
  compaction, and final-answer acceptance.
- `src/acp.rs`: Connection-owned prompt tasks, active sessions, headless
  execution, and the existing session shell-process owner.
- `src/sessions.rs`: Child session relationships, transcripts, and cost.
- `src/tools.rs`: Tool context, schemas, dispatch, and permission classification.
- `src/openrouter.rs` and `src/compaction.rs`: Role-specific request schemas,
  message projection, input admission, and summarizer material. The OpenRouter
  test fixture currently chooses replies by global request arrival order.
- `src/acp/convert.rs`: ACP identity, permission content, replay, and usage.
- `src/system_prompt.rs`, `src/hooks.rs`, `src/cancellation.rs`, and
  `src/process.rs`: Captured instructions, hook execution, cancellation, and
  foreground process cleanup.
- `~/src/taikonaut/src/tools/top_level.rs` and
  `~/src/taikonaut/src/runtime/{agent,registry}.rs`: Asynchronous starts,
  retained conversations, capacity, follow-up work, and failure isolation.

## Decisions

### One loop and shared resources

Keep the loop in `src/acp/prompt.rs` and rename its state from `PromptRun` to
`AgentTurn`. The prompt run remains the owning concept. The loop continues to
use ACP types and `acp::convert`; its location reflects that dependency.

Every subagent uses the main prompt's captured model, effort level, session
mode, workspace path, global hooks, and workspace instructions. Its initial
input is the assigned text as `TurnInput::UserMessage`. Its transcript is
fresh, and a short role instruction explains that its final answer goes to
the main agent.

Pass the active session's existing `ShellProcesses` clone to every agent.
They can inspect and control the same background commands. Stopping a
subagent cancels its current turn; foreground commands and hooks follow their
existing cancellation paths. Background commands remain available until
explicitly stopped, the session is deleted, the connection shuts down, or
headless execution ends.

### Tools and follow-up work

The main agent keeps all existing tools and gains these coordination tools.
Subagents have only the existing workspace and shell tools.

| Tool | Arguments | Behavior |
| --- | --- | --- |
| `start_subagent` | `{prompt}` | Starts work and returns a subagent ID immediately. |
| `send_message` | `{subagent_id, message}` | Starts another turn if idle, otherwise queues the text for after the current turn. |
| `stop_subagent` | `{subagent_id}` | Cancels the subagent, discards queued work, and awaits its current task. |
| `wait` | `{seconds}` | Waits for reports, all subagents to become idle, cancellation, or timeout. |

A subagent that needs input ends its turn with a question. Its answer is
forwarded just like any other final answer. The main agent replies with
`send_message`. Each queued text becomes an ordinary user message starting
another turn, in acceptance order. A busy subagent finishes its current turn
before reading queued work. Interrupting that work requires stopping it.

Use the same role for advertised schemas and dispatch checks. Invented
coordination calls from subagents, malformed arguments, and unavailable IDs
produce failed tool outcomes.

Keep at most four live subagents, including idle ones. A full owner rejects a
start immediately with the limit and current states. IDs are the child
session UUIDs and resolve only through this prompt run's owner.

Waits accept finite numeric seconds, treat nonpositive values as zero, and
cap one wait at 600 seconds. Queued reports, no subagents, or all subagents
being idle cause an immediate return. A wait reports its reason and current
states; it leaves report bodies for the main loop to save and deliver.
Register for notification before checking state so a completion cannot be
missed between the check and the wait.

Apply the existing tool-result size conventions to coordination output.
Reject oversized assigned tasks and follow-up messages before accepting them.
Bound forwarded answers and failures with an explicit truncation marker; the
complete accepted answer remains saved in its child session. Each turn and
received report batch still passes the existing context admission.

### A small subagent owner

`Subagents` is a prompt-owned guard over shared state: a map of subagents,
a queue of reports for the main agent, and a notification. Each map entry
holds its child session ID, queued work, busy/idle/stopping state, cancellation,
and task handle.

An idle subagent needs no running task. Starting work spawns a Tokio task.
That task runs the shared loop, publishes its result, and takes the next
queued input or marks the subagent idle and returns. Queue inspection and
the transition to idle happen under the same mutex used by `send_message`.
Publish a report and the resulting state together before notifying the main
agent. Keep asynchronous work outside the mutex.

Tasks receive shared state handles, not ownership of the prompt guard.
Dropping `Subagents` closes admission, discards queued work, and signals
cancellation even while task handles still reference the shared state. Each
task also observes parent prompt cancellation and signals its own turn's
cancellation. Stopping one subagent does not cancel the others.

The main prompt stays in `connection.spawn`. Subagent tasks use
`tokio::spawn` and turn their errors into reports; they never return errors
through the ACP connection task mechanism.

On a normal return or cooperative cancellation, close the owner, cancel
remaining subagents, and await their current tasks before the main agent's
`after_run`. Allow each child loop to attempt its interrupted batch save.
A dropped prompt future can only signal cancellation through its guard;
detached child tasks may finish unwinding afterward while the runtime remains
alive. They write only their child sessions and cannot delay a subsequent
main-session operation. No guarantee of a completed save is made for abrupt
transport loss or process exit.

A dropped owner's reports are discarded. If its child session has already
been deleted, a late save fails normally and does not recreate it. The
existing active-session shell owner continues to handle connection and
headless shutdown.

### Child sessions and reports

Add an optional `parent_session_id` to session rows and an internal child
creation operation. Reuse the existing transcript, turn-start, batch, hook,
and compaction code for child sessions.

Only main sessions appear in normal ACP listing and accept ACP operations.
Deleting a main session cascades to its children. Reloading creates no
subagent tasks. Saved child sessions remain available for inspection and cost
accounting, including children from earlier prompt runs.

Add `TranscriptEntry::AgentMessages` only to the main transcript. Each
`AgentMessage` contains `subagent_id` and either a final answer or a failure.
It needs no general sender field or explicit-message kind. Subagent assigned
tasks and follow-up work use the existing `TurnInput::UserMessage` variant.

Only the main loop drains and saves reports. Child tasks publish to the
in-memory queue and never append to the main transcript. Report order is
publication order; no global sequence counter is required. A successful
subagent turn forwards the committed answer accepted by its global
`before_stop` hooks after `after_run` completes. Model failures, refusals,
token limits, and hook failures produce failure reports and end that
subagent. Ordinary failed tool outcomes retain their existing behavior.

### Main-loop delivery and stopping order

Before an ordinary model request, admit and save any queued reports, then
project the request. Keep reports outside complete assistant batches and
the hook feedback belonging to those batches.

For a completion with tool calls, commit the batch, send usage, and run
`after_tools`. The next request boundary then receives reports.

For a completion with a finished stop, use this order:

1. Commit the assistant batch and send usage.
2. If this is the main agent, check its report queue. When reports are
   pending, admit and save them, then continue the turn without running
   `before_stop` on that answer.
3. Otherwise run `before_stop`. A hook continuation reaches the next request
   boundary; an accepted stop ends the turn and begins owner shutdown.

The inbox check is the completion boundary. Reports arriving while stop
hooks run are consumed if a hook requests continuation; otherwise shutdown
may discard them. Do not add a second check after the hooks that could
invalidate the answer they just judged. Subagents have no mid-turn inbox
check.

Ox still forwards provisional answer text while streaming. This ordering
prevents the stop hook from judging an already superseded answer; it does
not retract text already displayed by the ACP client.

### Presentation, permissions, and hooks

Replace `send_update` and `PermissionTransport` with one `Presentation`
value, constructed for three uses:

| Use | Updates | Permissions |
| --- | --- | --- |
| Main agent over ACP | Sent to the main session | Requested through that connection |
| Subagent over ACP | Suppressed | Requested through the main session's connection |
| Headless execution | Suppressed | None; the captured mode is Auto |

`Presentation` owns the connection and an `AcpIdentity`: the main session
ID plus an optional subagent ID. Store identity remains the agent's own
`SessionSummary.id`. Every permission request uses the ACP identity's main
session ID, including requests from subagents. Scope ACP tool-call IDs and
labels here with the optional subagent ID; preserve the original model call
ID in the transcript and OpenRouter requests.

Ask mode still requests approval for each agent's shell starts and
shell-process writes. A subagent start grants no shell approval. Auto mode
remains automatic. Permission content includes the subagent ID and complete
command or input.

Show main-agent coordination tools as ordinary ACP tools. Present saved
reports as attributed tool content using the same live and replay projection.
Child answer, reasoning, and tool updates are suppressed.

Global hooks run for both roles. Invoked skill hooks belong only to the main
agent. Each child turn receives its own session ID and run ID through the
existing hook context; no extra hook fields are needed. Follow-up turns run
the normal lifecycle hooks, and their text is not dispatched as a slash
command. Preserve inherited global-hook suppression. Hooks report their own
agent's batch while other agents may change the shared workspace.

### Usage

Only the main agent sends usage updates, at its existing commit and
compaction points plus once after normal subagent shutdown. Reload and
`/compact` also use the aggregate cost.

Context usage describes the main transcript. Session cost is the main
transcript's saved cost plus a store query summing saved model and summarizer
costs across its child sessions. A wait returning commits a batch and therefore
refreshes the total when the main agent observes progress. Child commits
perform no ACP reporting. A late child save after abrupt prompt loss is
included in a later cost query.

## Naming

Use existing glossary terms, with these additions:

- **Subagent**: An agent owned by one main prompt run. `Subagents` is its
  prompt-owned guard and shared coordination state.
- **Child session**: A saved session linked to the main session through
  `parent_session_id`. Its ID is the `subagent_id` in coordination tools.
- **Agent turn**: One execution of the shared loop. `AgentTurn` replaces
  the struct name `PromptRun`; the prompt run remains the overall operation.
- **Agent message**: A subagent final answer or failure published to the main
  agent, represented by `AgentMessage` and saved in `AgentMessages`.
- **ACP identity**: The main session ID and optional subagent ID used for ACP
  presentation and permission requests. Use `AcpIdentity`.
- **Presentation**: The connection, ACP identity, and choice of sending
  updates used by the loop. Use `Presentation`.
- **Tool context**: The workspace path and shared shell-process owner passed
  to tool execution and permission classification. Use `ToolContext`; add
  the role and main agent's coordination handle with the feature.

## Test plan

Before concurrency tests, extend the OpenRouter fixture with request-content
routing. Use distinct task text to select a script with its own reply queue;
retain the current sequential constructor for existing tests. Add an explicit
release gate to a reply when a test must hold a request in flight. Routing
chooses the right response regardless of arrival order; gates establish the
specific overlap the test needs.

- Keep existing loop, shell cleanup, and hook tests with their current owning
  guarantees through the preparatory refactors.
- Test overlapping subagents and FIFO follow-up turns, retained transcripts,
  fresh initial context, inherited settings and instructions, independent
  compaction, and automatic final answers or failure reports. Use routed
  fixture replies and gates instead of scheduler timing.
- Test the owner and tool boundaries for capacity including idle entries,
  role restrictions, ID scope, queued work, stopping, bounded output, and
  waits observing completion, timeout, and cancellation.
- Test main report delivery outside batch/hook sequences and before
  `before_stop`, including a hook that must not receive a superseded answer.
  Cover report encoding, replay, and compaction at their existing boundaries.
- Test subagent Ask requests under the main ACP session ID with scoped
  tool-call IDs, approval and denial, shared shell-process access, and global
  versus invoked-skill hook scope.
- Test normal cancellation and dropped-owner cancellation with a held child
  turn. Verify child save attempts remain isolated from the main transcript
  and that a shared background command survives stopping its subagent.
  Existing session cleanup tests continue to own background-command shutdown.
- Test hidden child sessions, cascade deletion, reload without execution, and
  aggregate cost including stopped children and earlier prompt runs. Verify
  only main-agent update points send usage.

## Implementation plan

1. **Preparatory commit: presentation and tool context.** In
   `src/acp/prompt.rs`, combine update sending and permission transport into
   `Presentation`. Put main-session routing and scoped tool-call identity
   there, with conversion helpers in `src/acp/convert.rs`. Adapt ACP and
   headless callers and preserve the test observation seam. In `src/tools.rs`,
   introduce `ToolContext` for `execute` and `permission`, initially holding
   only the existing workspace path and shell owner. Preserve current behavior
   and validate this commit independently.
2. **Mechanical commit: name the shared loop.** Rename `PromptRun` to
   `AgentTurn` in `src/acp/prompt.rs` and direct code references. Keep the
   module and the existing prompt-run terminology.
3. **Storage and projection.** In `src/sessions.rs`, add child creation,
   root-only ACP selection, cascade deletion, aggregate child cost, and
   `AgentMessages` append and validation. In `src/openrouter.rs` and
   `src/compaction.rs`, encode reports and include them in summarizer material.
   Keep `TurnInput` unchanged. Add the routed fixture before writing tests
   that issue concurrent requests.
4. **Subagent execution.** Add `src/subagents.rs` and its declaration in
   `src/main.rs`. Implement the map, pending work, report queue, notification,
   Tokio task startup, cancellation guard, and normal awaited shutdown.
   Drive each input through the shared loop against its child session, using
   the active session's shell owner and global hooks. In
   `src/system_prompt.rs`, derive the child prompt from the captured
   instructions and `src/prompts/subagent_prompt.md`.
5. **Coordination tools and loop integration.** Add `src/tools/subagent.rs`
   for the four main-agent schemas, validation, and rendering. Extend
   `ToolContext` with role and coordination access. Use that same role in
   `ModelRequestParameters` so actual requests and estimates advertise the
   correct tools. Integrate main report intake and the stated stop order in
   `src/acp/prompt.rs`.
6. **ACP integration and validation.** In `src/acp.rs`, pass the shared
   owner and captured inputs while retaining connection-owned main prompts.
   In `src/acp/convert.rs`, add report presentation and aggregate usage at
   main update points. Add the tests at their owning boundaries, then update
   the documentation below.
