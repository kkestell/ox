# Global hooks

## Goal

Run hooks from `~/.config/ox/settings.json` alongside the invoked skill's
hooks. Reuse the existing hook definitions, command runner, lifecycle points,
and feedback entries. At each point, run the global command followed by the
skill command.

Follow [architecture](../architecture.md), [code style](../code-style.md),
[glossary](../glossary.md), and [testing](../testing.md).

## Related code

- `src/skills.rs`: reusable `Hooks`, `HookCommand`, and command validation.
- `src/hooks.rs`: `SkillHooks`, JSON input, and execution of one command.
- `src/acp.rs`: process state, skill dispatch, and headless entry point.
- `src/acp/prompt.rs`: the five hook points and feedback saving.
- `src/sessions.rs`: feedback attribution and placement validation.
- `src/acp/convert.rs`, `src/openrouter.rs`, `src/compaction.rs`: hook labels
  in ACP updates, model requests, and compaction text.

## Decisions

### Configuration

Use the existing hook definition shape in JSON:

```json
{
  "hooks": {
    "before_tool": { "command": "python3 scripts/check.py" },
    "after_run": { "command": "python3 scripts/report.py" }
  }
}
```

Support the same five hook kinds and one command per kind. Reuse their
existing deserialization and validation. Missing settings or omitted `hooks`
means no global hooks; invalid settings fail with an error naming the file.
Use `$HOME/.config/ox/settings.json` and the existing bounded UTF-8 reader.

Read settings once when starting the ACP server or a headless run. Keep ACP
global hooks in `ServerState`; restarting Ox picks up edits. Commands run in
`~/.config/ox`, and their existing `workspace` input identifies the session
workspace. Configured hooks run in both Ask and Auto mode.

### Execution

Change the prompt run's optional hook definition into a list containing the
global definition and then the invoked skill's definition, when present. At
each existing hook point, directly iterate over the definitions that declare
that kind. Keep the current single-command runner.

Both commands run even when the first returns a denial or continuation:

- `before_run` and `after_tools`: save each message as it arrives.
- `before_tool`: deny if either command denies; report the denial messages in
  execution order. Otherwise proceed to the existing permission request.
- `before_stop`: continue if either command requests continuation. Save each
  message and count one continuation for the resulting model request.
- `after_run`: attempt both commands, keeping the existing best-effort error
  reporting and unchanged prompt result.

Ordinary hook errors still end the prompt run, and cancellation still stops
new work. A previously saved message remains saved when the next hook fails.
Build each event's input once before the loop, particularly `after_tools`,
whose input currently reads tool results from the transcript's tail.

Global hooks apply to ordinary ACP and headless prompts. When launching any
hook command, set an inherited `OX_IN_HOOK=1` environment variable. Ox skips
global hooks when that variable is present, so a hook's nested `ox run` does
not invoke them recursively. This also keeps the existing goal skill's nested
judge independent of global hooks. `/compact`, replay, and compaction model
requests keep their existing paths outside hook execution.

### Feedback

Make `skill` optional in the hook definition passed to the prompt run, hook
input, and saved feedback. Global hooks use `null` and empty `arguments`;
skill hooks retain their current values. Use one shared label function to
identify global hooks and named skill hooks in existing displays and errors.

Keep separate feedback entries. Permit adjacent entries of the same hook kind
by checking their placement against the preceding non-feedback entry. Allow
`before_run` after either a user message or skill invocation. A named skill
must still match the current skill invocation, and the other placement rules
remain. Execution order belongs to the prompt loop; transcript validation
needs no additional rules for global-versus-skill ordering or counts.

## Naming

- **Global hooks**: hook commands from the user's settings file, available to
  prompt runs across workspaces. Use `global_hooks` in process state.
- **Hook**: an external command declared globally or by a skill for an existing
  hook kind.
- **Hook feedback**: the existing saved message and optional stop decision,
  with an optional skill name identifying its origin.
- `RunHooks`: rename `SkillHooks`; retain its commands and directory and add
  the optional skill name. A prompt run holds `Vec<RunHooks>`.
- `OX_IN_HOOK`: inherited marker identifying processes descended from a hook
  command, used to suppress nested global hooks.

## Implementation plan

1. Move `Hooks` and `HookCommand` to `src/hooks.rs` and expose their validation.
   Add a small `src/settings.rs`, registered in `src/main.rs`, to load the JSON
   into the existing definitions and supply their directory.
2. Load global hooks at the two entry points in `src/acp.rs`. Pass global and
   skill definitions through the existing `PromptInput.hooks` field. Tests
   supply their own definitions rather than reading the user's settings.
3. Add the direct loops in `src/acp/prompt.rs`, pass the current definition to
   the existing execution and feedback helpers, and set the inherited marker
   in `src/hooks.rs`.
4. Make skill attribution optional and adjust feedback placement in
   `src/sessions.rs`. Update the existing label call sites in
   `src/acp/convert.rs`, `src/openrouter.rs`, and `src/compaction.rs`.

## Test plan

- Test the settings loader against an explicit temporary path: missing file,
  valid definitions, malformed JSON, and invalid commands. Cover suppression
  by the inherited marker without mutating the test process's environment.
- Extend the existing lifecycle test with ordinary global-only and combined
  global/skill runs: both commands run in order, use their own directories,
  and deliver feedback to the model. Cover denial and continuation decisions
  from either command, counted once per point, and both `after_run` attempts.
- Extend session validation and replay cases for global feedback and adjacent
  feedback of the same kind; retain rejection of misplaced feedback and a
  mismatched skill. Extend compaction coverage for global feedback labels.
- Extend headless coverage for top-level global hooks and a nested invocation
  inheriting the marker. Reuse existing hook error and cancellation coverage.
