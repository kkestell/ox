About Ox

ACP-first and client-independent
Ox is a real ACP v1 agent rather than an editor-specific bot. It can run in Zed, its own browser client, or another ACP client. When supported, it delegates filesystem and terminal operations back to the client—important for unsaved editor buffers—without changing Ox's validation, permission, or cancellation rules.
Exceptionally strong session recovery
Sessions are append-only, durable logs that preserve exactly what the model saw and what the user saw. Ox can replay a conversation, resume without replay, and even recover a turn paused on a permission request. Crucially, it distinguishes “never dispatched” from “possibly executed,” so a crash cannot cause it to blindly repeat a shell command or external mutation.
Replay and model context are separate
Long conversations can be compacted for the model while the original transcript remains intact for the client. Summarization preserves the system prompt, first user request, recent tool-call groups, todo state, and configuration. This is considerably more careful than simply replacing old chat messages with a summary.
Genuinely concurrent subagents
A primary agent can run bounded tasks in parallel, message children while they work, receive interim reports, wait without polling, and cancel them cleanly. Children get private conversations but share the turn's frozen model configuration, workspace, skills, MCP activation, and permission grants. Their private chatter is deliberately excluded from durable transcript history.
Permission semantics designed around actual operations
Reusable shell approval is derived from parsed command structure, not naïve string prefixes. MCP grants are tied to the server, tool, and unchanged definition. Exact file edits must match current content exactly once. Plan mode removes mutating tools at the dispatcher rather than relying on prompt instructions.
Frozen, reproducible activations
Instructions, skill identities, model profiles, tool schemas, and MCP catalogs are fixed when a session activates. If a skill or MCP tool changes underneath the session, Ox refuses to combine the old authority or metadata with the new implementation. That protects permissions, reproducibility, and provider prompt caching.
Deep language-server integration
Definitions, references, symbols, and diagnostics come from explicitly configured LSP servers. Ox synchronizes current document content, handles position encodings, confines returned paths to the workspace, and never presents stale or timed-out diagnostics as a clean result.
A capable first-party browser client
Its Bun host remains alive without a browser attached, supports multiple workspaces and concurrent conversations, and can be used from desktop or mobile over a trusted network. Refreshing or disconnecting the browser does not cancel active work, and background conversations remain visibly supervised.
Explicit, bounded workspace memory
Memory is opt-in rather than silently extracted from transcripts. Facts have types, provenance, expiry, supersession, capacity limits, and workspace scoping. Retrieval is recorded in the session history, so later memory changes cannot rewrite what an old conversation saw.
Careful external-content handling
Web pages, MCP results, and stored memories remain untrusted data, never system authority. Web fetch blocks private-network destinations and redirect tricks. Large results are bounded and spilled rather than flooding model context.
Privacy-preserving diagnostics
Optional JSONL traces record timing, identifiers, sizes, and outcomes—but intentionally exclude prompts, model text, tool arguments, file contents, shell output, credentials, and raw errors.
Small operational footprint
Despite all of that, Ox ships as a single self-contained Go binary of roughly 11 MB, backed by deterministic process-level and end-to-end tests.
