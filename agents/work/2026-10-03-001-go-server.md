# Rewrite the Ox server in Go

## Plan

No plan file. The goal was to rewrite `crates/ox-server` in Go with OpenRouter
as the only provider, port the tests that add real value, and run live tests
with `openrouter:deepseek/deepseek-v4.1-flash` at major milestones.

## Summary

The Ox server is now `server/`, a Go module that builds `ox-server`. The Rust
crate `crates/ox-server` is deleted. The terminal client `ox` stays in Rust;
`ox run`, `ox acp`, and `ox auth` exec `ox-server` with the same arguments, and
the bundled server is the `ox-server` next to `ox`. The ACP wire format, the
OpenRouter request bodies, the SQLite schema, and the stored transcript JSON
match the Rust server, so the client, Zed, and the scripts that read `ox.db`
work unchanged.

The server is about 7,000 lines of Go plus 2,600 lines of tests, in one package
per concern under `server/internal/`: `catalog`, `transcript`, `store`,
`openrouter`, `settings`, `skills`, `sysprompt`, `textfile`, `tools`,
`shellproc`, `agent` (one turn, with no ACP knowledge), `acp` (JSON-RPC
transport and wire types), `server` (sessions over one ACP connection), and
`keyring`. Its direct dependencies are `github.com/ncruces/go-sqlite3` (SQLite
without cgo), `go.yaml.in/yaml/v3` (skill frontmatter), `golang.org/x/term`
(hidden key entry), and `golang.org/x/sys` (atomic no-replace moves). The
client's dependency tree fell from 370 to 184 crates.

## Departures from the Rust server

- OpenAI support is removed: no ChatGPT sign-in and no `openai:` models.
  `ox auth login openai` is an error, and a session saved with an `openai:` turn
  start no longer loads.
- `reasoning_details` continuation metadata is sent for every saved assistant
  message that has it, since every turn is an OpenRouter turn.
- A request rejected as too large for the model context ends the turn with the
  saved turn error "the session exceeds the model context limit; start a new
  session" instead of crashing the server.
- A failed read of a command's output pipe is reported as a diagnostic line and
  no longer marks the command failed. Background processes are running, exited,
  or stopped.
- File tools open paths through `os.Root`. A link inside the workspace that
  points inside it is followed when a file is opened; no path or swapped-in link
  can reach outside the workspace. Patch targets still reject links, parent
  traversal, and duplicate targets during preparation as before. Moves open both
  parent directories through the workspace and use an atomic no-replace rename
  on macOS and Linux.
- `grep` patterns use Go's RE2 syntax, and its tool description says so. Glob
  filters use a ripgrep-style matcher in `tools/glob.go`: a glob without a slash
  matches a file name at any depth, and `*`, `?`, `**`, classes, alternatives,
  and a leading `!` are supported.
- The system prompt's platform line uses Go's names, such as `darwin (arm64)`.
- The keyring is reached through `security` on macOS and `secret-tool`
  elsewhere. On macOS this is the same keychain item the Rust build used, so a
  saved key carries over. `ox auth login openrouter` also reads the key as one
  line of standard input when stdin is not a terminal.
- The internal error returned for a failed prompt carries the saved turn error
  text, including its reason prefix.
- Background process IDs are random base32 strings instead of UUIDs.
- Error wording from JSON decoding and argument validation follows Go's
  messages. An explicit `null` for `read_file`'s `offset` or `limit` means the
  default.

## Tests

Ported, as Go tests: catalog filtering; request encoding, including grouped tool
results, continuation metadata, images, effort, and provider pins; stream
assembly of fragmented tool calls and reasoning details; finish reasons;
malformed streams and failed statuses; stalls; key verification; transcript
storage across reopen; rejection of malformed transcripts; title adoption;
listing and deletion; settings loading, workspace overrides, and saving; skill
loading and priority; system prompt bounds; read paging; search filtering,
truncation, and unreadable files; glob matching; every patch behavior; shell
argument validation, output, environment, timeout, cancellation, and process
group cleanup; background processes, input, stop, and the process limit; the
turn loop with permission, cancellation, retries, update failures, images, and
context overflow; and the ACP session lifecycle, configuration, skill dispatch,
prompt validation, close, and shutdown at end of input.

Startup signal tests cover cancellation of catalog requests in ACP and headless
runs. Concurrent move tests check that exactly one move to a destination
succeeds and the other sources remain unchanged.

Prompt responses are sent after releasing the session for its next operation;
shutdown still waits for those responses to finish. This fixes an intermittent
rejection of back-to-back prompts found by the skill dispatch test.

Not ported: the OpenAI tests; the connection-reuse test, since Go's HTTP client
owns pooling; the descriptor tests for delete and move link swaps, which
`os.Root` guarantees; and the unit tests of private helpers that the behavioral
tests above cover.

The client's scripted OpenRouter moved to `crates/ox/src/fixture.rs`, shared
with `crates/ox/tests/tui.rs`. Client tests now start the real `ox-server`
binary instead of an in-memory server. Four model picker tests changed their
expected model count from six to four because the fixture catalog no longer
holds OpenAI models.

## Manual verification

Live runs with `openrouter:deepseek/deepseek-v4.1-flash` and the key in `.env`:

- `ox-server run` in a temporary workspace: the model ran a failing test, found
  the bug with glob and `read_file`, fixed it with `apply_patch`, and reran the
  test. The run exposed two bugs, both fixed and covered by tests: glob printed
  `././` paths, and foreground commands got a closed stdin instead of
  `/dev/null`.
- `ox acp` driven over ACP in Ask mode: the model started a background HTTP
  server, read its output, called it with `curl`, and stopped it; then wrote,
  read, and searched a file. Shell calls asked for permission and
  `shell_process` reads and stops did not. Listing, reloading with replay, and a
  clean exit at end of input worked.
- The TUI in tmux in Auto mode ran a shell command and answered with its output.

An ACP session scripted against a fake OpenRouter produced the same messages
from the Rust and Go servers apart from random IDs, and the same OpenRouter
request bodies apart from the platform line and the `grep` description.
