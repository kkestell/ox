## F1. Claude inherits settings that override the effort and billing Ox shows

Medium · Settings · Plan

Ox starts Claude with its own environment minus `ANTHROPIC_API_KEY` and `ANTHROPIC_AUTH_TOKEN`. Claude Code reads other variables that override what Ox passes or chooses. `CLAUDE_CODE_EFFORT_LEVEL` overrides `--effort`: Claude Code 2.1.331 describes it as "overrides effort for this session". A user with it set in their shell sees the effort they picked in Ox while Claude runs at another, for sessions and for titling. `CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_VERTEX`, and `CLAUDE_CODE_USE_FOUNDRY` send Claude to another provider and its billing instead of the user's subscription.

This breaks **Settings shown are settings used**, **Titling model**, and **Subscription billing**.

### Places

- `internal/claude/claude.go:168`: `subscriptionEnv` strips only the two credential variables.
- `internal/claude/claude.go:110`: the launch passes `--effort`, which the inherited variable overrides.
- `internal/claude/ask.go:25`: titling starts Claude with the same environment.

### Evidence

Reproduced with a stand-in `claude` through `claude.Ask`, which received both `CLAUDE_CODE_EFFORT_LEVEL=high` and `--effort=low`. The override is confirmed from the strings in the installed Claude Code 2.1.331 binary. The effective effort and a third-party provider's billing were not observed live.

### Origin

`7827b93`, "Keep Claude off an inherited Anthropic API key", which named only the API key; no review.

### Action

Remove from Claude's environment every variable Claude Code reads that changes the effort, model, permission mode, provider, or account Ox chooses, in one list beside the credential variables. Extend `TestClaudeStartsWithoutAnAPIKey` in `internal/claude/claude_test.go` to set each and check the stand-in never sees it. Record the variables in `docs/harnesses/claude-code.md`. The change alters nothing the user sees except that Ox's settings hold. Issue #105.

## F2. A file that changes type breaks the whole Changes tab

Medium · Correctness · Plan

When a tracked regular file becomes a symlink, or the reverse, `git diff --numstat -p` gives one numstat record and two patch sections, the old type's deletion and the new type's addition. `parseDiff` requires one section per record and fails the whole listing, so the Changes tab shows `list changes: 1 numstat records but 2 patch sections` in place of every changed file, on every poll, until the change is undone.

This breaks **Changes view**, **Change diffs**, and **Changes updates**.

### Places

- `internal/server/changes.go:264`: `parseDiff` pairs records and sections one to one.
- `internal/server/changes.go:112`: the diff command.

### Evidence

Reproduced through `workspace/list_changes` and with Git alone: replacing a tracked file with a symlink gives one numstat line and two `diff --git` sections.

### Origin

`5dbd0b3`, "Add a Changes tab that shows the session's diff (#100)"; review `agents/reviews/2026-11-25-changes-view.md`.

### Action

Pair sections with records by path, so a type change's two sections form one file. Add the case to `TestListChanges`. Issue #106.

## F4. Stop stays hidden after a reconnect

Medium · Requirements · Plan

Stop sets the page's `stopping` flag, which hides the Stop button. Only a published state other than running clears it. When the page misses that transition, because it reconnected while a later turn was already running, the flag survives and Stop stays hidden for the whole turn. A message or report taken during the interrupt can do the same without a reconnect, since the published state can stay running from one turn into the next.

This breaks **Stop**.

### Places

- `cmd/ox/web/src/ox.tsx:429`: `interrupt` sets `stopping` and clears it only on refusal.
- `cmd/ox/web/src/ox.tsx:550`: `setState` clears it only on a state other than running.
- `cmd/ox/web/src/SessionView.tsx:146`: Stop shows only while `stopping` is false.

### Evidence

Reproduced with the production page modules under a simulated transport: an acknowledged interrupt, a disconnect, and a reconnect snapshot of a later running turn left `stopping()` true.

### Origin

`d079e3a`, "Show actions at once, and session status on first load (#66)"; review `agents/reviews/2026-11-23-optimistic-ui.md`.

### Action

End the flag with the request it belongs to rather than with a state transition the page may never see: clear it when the interrupt's reply settles, or tie it to the turn it stopped. Extend the Stop specs in `session.spec.ts` with a reconnect during a later turn. Issue #111.

### Places

- `internal/server/session.go:628`: `report` replaces the turn at its result.

## F20. A second Ctrl-C misses an oxd that make dev is restarting

Low · Settling · Plan

When `make dev` restarts a changed `oxd`, it drops the old process from its records before the process exits. Ctrl-C and a second Ctrl-C signal only recorded processes, so the retiring `oxd` gets neither and the stack waits for its graceful stop.

### Places

- `cmd/ox/web/stack.mjs:112`: `restart` clears `record.proc` before awaiting the old process.
- `cmd/ox/web/stack.mjs:156`: the SIGINT handler signals recorded processes only.

### Evidence

Reproduced with the production `runStack` and a stand-in daemon that records signals: after a rebuild's SIGTERM, two SIGINTs reached nothing.

### Origin

`c3b56a9`, "Restart changed binaries in place under make dev"; no review.

### Action

Keep every process the stack has signaled and not seen exit where both signal handlers reach it. Add the case to `stack.test.mjs`. Issue #104.
