## Findings

### F1. Reply text shown live is lost on an abrupt `oxd` exit

**Medium · Broken guarantee · Older (`94af566`) · Fix, or narrow the promise with the user**

`internal/server/history.go:18-28` keeps consecutive `text_delta` fragments in `h.pending` and writes them only when another kind of update arrives. `session.go:366-373` broadcasts each delta at once, and `session/get` includes the pending tail (`history.go:83-84`). On startup, `recordEnd` (`history.go:37-43`) has only SQLite, so it appends `parked` to a history without the reply.

Reproduced independently by two reviewers:

- A stand-in Claude emitted a delta and then waited.
- The text showed in the notification and in `session/get`.
- After `SIGKILL` and a reopen, the history was `[prompt, parked]` with no reply.
- A `SIGTERM` control run kept the text.

`docs/protocol.md:292-296` and **Surviving restarts** promise that transcripts survive restarts without distinguishing graceful from forced exits. **Database failures** does not apply, because the database was writable. The existing tests reload only after a flush (`TestHistoryMergesTextAndKeepsConversation`), and the forced-restart e2e stops at a tool call, which flushes first. F2 makes this loss routine under `make dev`.

Correction: bound the unflushed tail by writing the pending text on a short timer or a size limit, or record each delta. If the product accepts losing it on a crash, the user rewords the requirement and the protocol passage.

### F2. One Ctrl-C under `make dev` forces `oxd` past graceful shutdown

**Medium · Broken guarantee · Older; kept by `c3b56a9` · Fix**

`stack.mjs:40` spawns services in the terminal's process group, so a terminal Ctrl-C sends `SIGINT` straight to `oxd`. `dev.mjs:15` also handles that `SIGINT` with `stack.stop(130)`, which sends `SIGTERM` to every child (`stack.mjs:30-35`). `cmd/oxd/main.go:78-97` treats a second signal as a forced stop: `claude.KillAll(); os.Exit(1)`, without waiting for `s.Close()`.

A probe in a private process group, using `runStack` and the real dev `SIGINT` handler, showed that one `kill(-pgid, SIGINT)` delivered both `SIGINT` and `SIGTERM` to the stand-in. The forced exit of the real daemon is traced from source.

Every Ctrl-C of `make dev` therefore skips the shutdown that **Stopping oxd** describes:

- Pending history is not flushed (F1).
- `parked` is not recorded and is repaired only on the next start.
- Claude processes are killed, not stopped.

The existing stop test calls `stack.stop(0)` directly and does not see the terminal's broadcast.

Correction: spawn the services in their own process group (`detached: true`), or have the stack skip signalling children that already received the terminal's signal.

### F3. `create_session` publishes the child before its first message has an owner

**Medium · Broken guarantee · New (`6a4e230`; the archive path from `15d5cc5`) · Fix**

`internal/server/mcp.go:414-417` stores the child and calls `s.addSession`, which starts its goroutine and broadcasts `session/created` (`methods.go:375-386`). Only after that does the request post `created.acceptMessage(message)` (`mcp.go:430-441`). On any error, the request calls `created.destroy()`.

Two outcomes were reproduced with a gate placed just before `created.post`:

- **Archive.** A page archives the visible, parked child in the gap. The child correctly refuses the message with `session is archived`. Creation treats that refusal as a launch failure and deletes the child. The page sees Archive succeed and then `session/destroyed`. This breaks **Archived sessions** and **Deleting a session**.
- **Shutdown.** `Server.Close()` ends the child's goroutine in the gap. The post fails with `session not found` and nothing rolls back. After a restart, the empty child remains, and a retry with the same name returns `a child named "worker" already exists`. This breaks **Claude can start child sessions**.

Tests for the same handoff:

- `TestCreateSessionDuringShutdown` waits with `time.Sleep(100 * time.Millisecond) // the call reaches the parent's queue` (`mcp_test.go:489`). A gated probe made it fail. The sleep does not establish the order it assumes.
- The test's `c.received("")` (`mcp_test.go:509-513`) filters by exact session ID (`client_test.go:102-105`). It therefore matches no `session/created` notification and cannot see the side effect it claims to rule out.

Correction: hand the first message to the child as part of its creation, so the child's goroutine owns that input before the child is published. Only an unpublished child is rolled back. Replace the sleep with a gate, and match `session/created` by method.

### F4. Archive and unarchive act outside the owner of session membership

**Medium · Broken guarantee, docs · New (`15d5cc5`) · Fix**

`archiveSession` (`internal/server/methods.go:564-576`) looks up `sess` under `s.mu`, unlocks, then calls `change(sess)`. `unarchive` (`session.go:247-255`) takes the lock again without checking that `sess` is still a member. `setArchivedLocked` (`session.go:270-284`) writes SQLite by ID but sets `m.archived` on the captured pointer.

Reproduced by two reviewers, with the handler paused between lookup and mutation:

- Delete, then recreate the session with the same client-chosen ID and archive it.
- Release the stale unarchive. It succeeds and broadcasts `session/unarchived`.
- SQLite now has `archived=false`, while `workspace/list` still reports `archived:true`. A restart flips the replacement's state.
- Without ID reuse, a stale unarchive still broadcasts after `session/destroyed`.

This breaks **Archived sessions** and **Every page in sync**.

Archive has a related gap. `hold` (`session.go:199-205`) calls `sess.stop()` after the release, and the method replies without waiting. A probe matched the reply and `parked` in one predicate and got the reply first, three times out of three. `TestArchive` uses separate waiters, so either order passes.

`docs/architecture.md:50-57` says every request for a session is posted to its goroutine and queues its response there. Archive replies from the request goroutine, and unarchive touches no goroutine. `docs/architecture.md:67-73` gives the archive condition as "idle or parked", but `hold` also accepts `background`.

Correction:

- Make unarchive one critical section under `s.mu` that looks the session up by ID, checks the parent, stores the flag, and broadcasts.
- Decide whether archive success means the stop has happened. If it does, wait for the members' stops before replying, and test the order in one predicate.
- Correct the two architecture paragraphs.

### F6. Only the socket, not the database, has one owner

**Medium · Broken guarantee · Older; the archive consequence is new in `15d5cc5` · Fix**

`cmd/oxd/main.go:60-73` takes the socket and then opens the database. The comment there says holding the socket protects the history repair, but a second `oxd` given a different `-socket` and the default database passes that check.

Reproduced with two real binaries:

- The second daemon's load appended `parked` to the first daemon's live history.
- Daemon B archived the session.
- Daemon A still listed the session as unarchived and accepted `session/send`.

This is a different trigger from the same-socket case fixed in the multi-lens review (F2). It breaks **One transcript**, **Every page in sync**, and **Archived sessions**. `TestDaemonOwnsSocketUntilShutdown` reuses both paths, so it tests socket exclusion only.

Correction: take an exclusive lock on the database (for example, `flock` on the database file or on a lock file beside it) before the repair, and hold it until shutdown.

### F7. A race report from a stopping `oxd` is lost in e2e and dev restarts

**Medium · Hollow tests · Older; the dev path is kept by `c3b56a9` · Fix**

`AGENTS.md` (Verification) says a data race stops `oxd` with its report and fails the test. That holds only while `oxd` runs.

- `e2e/services.ts:99-104`: `restartDaemon` awaits `stopProcess(daemon, signal)`, which resolves on `exit` without reading the status (`:116-121`). It then replaces the process.
- `stop()` (`:105-109`) checks `daemon.exitCode` only before it signals the daemon.
- The `exit` listener (`:81-84`) only logs.

A wrapper that exited with status 66 on `SIGTERM` made both `restartDaemon` and `stop()` succeed.

In `stack.mjs:61-68`, `restart` moves off the old process before seeing its exit status. A stand-in that exited 66 produced `restarted oxd`, and the stack kept running. `stack.test.mjs:125-132` kills the replacement, not the retiring process.

Correction: have `stopProcess` resolve with the exit result, and treat any status other than the expected signal or 0 as a failure in `restartDaemon`, `stop`, and the dev restart.

### F12. Session labels are derived on both sides of the protocol and drift

**Low · Duplication · Older; the reconnect case is new in `0fd3e2f` · Fix**

`oxd` derives a label from `store.FirstPrompt` with `strings.TrimSpace` (`internal/server/mcp.go:647-658`). The page derives its own from the transcript with `.trim()` (`cmd/ox/web/src/ox.tsx:72-80`). Three divergences were reproduced:

- **Reconnect.** The page keeps a `reloading` snapshot's old label over the fresh `workspace/list` label until `session/get` returns. This contradicts the comment at `ox.tsx:72-80`. Reproduced in Chrome.
- **Unicode trim.** A prompt of `"\u0085\nActual title"` shows `Actual title` from `oxd`. Once the session loads, the label is U+0085 only, because JavaScript's `trim` does not strip U+0085.
- **Failed write.** After a failed prompt write, the page shows the prompt while `list_sessions` and the next message's `from_label` use the ID prefix. Reproduced with a SQLite trigger.

The structural audit (its F3) rejected this consolidation because both sides agreed on visible inputs. The first two cases show they do not. Correction: `oxd` derives the label once and sends it in listings and snapshots, and the page shows what it receives (**Session labels**).

### F17. Highlighting alters carriage returns, colors substitutions as strings, and its test misses recomputation

**Low · Broken guarantee, hollow test · Local change · Fix**

- `FileView.tsx` renders `<pre role="tabpanel" innerHTML={html()} />` for every file. The HTML parser normalizes `\r` and `\r\n` to `\n`, so the pane's text differs from the file. Reproduced in Chrome. Before this change the pane rendered a text node, which keeps them. Requirement: **File viewer**.
- `style.css` has no `.hljs-subst` rule. Highlight.js nests substitutions inside `.hljs-string`, so `${hex}` takes the string color. GitHub's themes give substitutions the foreground color (`#24292e` light, `#c9d1d9` dark). The CSS comment "Text no rule colors keeps the pane's foreground" is wrong for nested tokens. Reproduced in Chrome.
- The `data-marked` assertion in `workspace.spec.ts` proves the DOM was not rewritten. The outer `html` memo guarantees that on its own. A mutation that removed the `text` memo and counted `highlight` calls still passed. The plan's no-recomputation decision is untested.

Correction: render the text-to-HTML conversion without normalizing line endings, for example by escaping `\r` or building the nodes directly. Add `.hljs-subst { color: var(--foreground) }`. Either test the memo directly or drop the claim that the test covers it.

### F19. `..` is cleaned before symlinks resolve

**Low · Broken guarantee · Older (`f2c49fd`); files part new (`da9f92d`) · Fix**

Both cases repeat the defect fixed for `workspace/create` (`methods.go:123-126`):

- `cmd/oxd/main.go:35-37` runs `filepath.Abs`, which lexically cleans an already absolute `-socket`. With `link -> other/inner`, `-socket base/link/../c.sock` bound `base/c.sock`, while `ox` dials the path as given (`cmd/ox/main.go:40,88`).
- `internal/server/files.go:39,54-56` opens `folder` through `os.Root`, but classifies links with `path.Join(folder, e.Name())`, which removes `..` first. For `alias/..`, the RPC enumerated `src` but classified its links against the workspace root. The web tree never sends `..`, so only RPC clients see wrong `folder` flags.

Correction: resolve without lexical cleaning in both places.

## Rejected

- **A directory named `__proto__` cannot expand in the tree** (Solid store key). Reproduced, but such a directory is not normal use (AGENTS.md, Implementation).
- **Streaming Markdown drops focus from a link while the reply grows.** Reproduced. The fix needs incremental Markdown rendering, which costs more than the defect.
- **The session control holds `sending`, `requested`, and `creating` as separate flags** rather than a union. No reachable overlap was found, and the composer serializes the three requests.
- **`mcp/attach` trusts a supplied session ID.** The socket is a trusted local API, and **Messages stay in Ox** concerns Claude Code's built-in messaging.
- **A failed `session/get` leaves the session reloading until the next connection.** Speculative: no common trigger was shown.
- **`protocol.ts` defines a narrower `ApprovalResponse` than the wire.** The page intentionally sends the narrower shape.
- **Product question, not a finding:** **Claude can start child sessions** can be read as allowing a permission-mode override. The tool inherits the parent's mode, as the creation plan chose. The user decides whether the requirement's wording should say so.
