## F1. The post-merge reset can discard uncommitted edits

High · Documentation · Plan

Workflow step 8 tells agents to reset the session's worktree after a pull request merges
when the two commit trees match. A user can edit a tracked file in that worktree while the
agent waits for the checks. The comparison still succeeds, and the prescribed reset
overwrites the edit.

### Places

`AGENTS.md:314`–`:318` checks the committed trees and then resets the worktree.

### Evidence

In a scratch repository, the documented comparison exited successfully while `git status
--short` showed a modified tracked file. Neither reviewer ran a destructive reset.

### Origin

`4452e91` added the reset step. No separate review record found.

### Action

Make the reset conditional on the worktree and index being clean as well as the committed
trees matching. Report remaining work before changing the checkout.

[Issue #146](https://github.com/kkestell/ox/issues/146)

## F2. Deleting an Ur session can leave its shell command running

High · Process I/O · Plan

If Ur has exited while one of its commands is running, Delete can reach the session
goroutine before the adapter handles the exit. Delete then succeeds and can remove the
worktree while the command is alive. The same stop path is used for daemon shutdown. This
breaks **Deleting a session**, **Ur's shell commands**, and **Stopping oxd**.

### Places

`internal/ur/agent.go:115` kills tracked groups on the process exit event. `:328` calls
`end`, which clears those groups and closes event delivery at `:358`.
`internal/process/process.go:131` closes `Reaped` before delivering the exit.
`internal/server/session.go:537`–`:552` stops the agent and waits only for `Reaped` before
removing the worktree.

### Evidence

The daemon reviewer used a stand-in Ur and a real `session/destroy` request over `net.Pipe`
and observed deletion return while its isolated sleep command was still alive. Handling the
exit first ended the command. Current source and `TestCrashEndsCommands` confirm that
cleanup depends on that event. The existing test processes the exit before issuing Stop.

### Origin

`ea7dd25` (#133), the Ur process separation. [Ur process review,
F2](../reviews/2026-11-26-run-ur-as-process.md#f2-a-crashed-ur-leaves-its-running-command-alive)
covered the exit-event route.

### Action

Give command cleanup and the session's completion wait one lifecycle owner across a normal
stop, an unexpected Ur exit, and their overlap. Verify deletion cannot settle before
cleanup.

[Issue #147](https://github.com/kkestell/ox/issues/147)

## F4. Stop and Send can reach the daemon in the opposite order from the clicks

High · Settling · Plan

While a turn is running, a steering prompt clears the composer as soon as Send is clicked.
Stop is then available while that send is in flight. If Stop arrives first, it ends the turn
and the pending prompt later starts a new turn. In the other order, Send is offered while
Stop is in flight, and a prompt entered after Stop can be canceled by that same Stop. This
breaks **Stop** on one page.

### Places

`cmd/ox/web/src/SessionView.tsx:168` chooses Stop as soon as the composer is empty.
`cmd/ox/web/src/ox.tsx:258` omits the stopping request from Send's gate.
`cmd/ox/web/src/connection.ts:127` uses independent POSTs, which the daemon posts in arrival
order.

### Evidence

The workflow reviewer reproduced each ordering in Chromium against real `ox` and `oxd` with
the fake harness, holding one POST at a time. The existing Stop specs wait for the preceding
daemon state, so they miss the crossing.

### Origin

The crossing predates `5a90074` (#126), which made it reachable through the combined button.
Earliest occurrence unknown. [Stop
review](../reviews/2026-11-25-fix-stop-hidden-or-ignored.md).

### Action

Give Send and Stop a coherent ordering at the session control. Verify both orderings through
held replies and notifications. Settle the visible behavior for the brief in-flight interval
in planning.

[Issue #148](https://github.com/kkestell/ox/issues/148)

## F5. A file tab can hide chat errors, recovery notices, and approvals

High · Requirements · Plan

A user can submit a draft, open a file in the same tab group, and then receive a create
error. The draft restores its text and settings, but the error is in the hidden chat.
Leaving and using Reopen draft can return to the same file tab. This breaks **Failed
creation** and **Every request settles**. The same tab choice can hide the review-and-send
notice when a lost create reply is recovered. No prompt is sent by recovery. The same hidden
chat also conceals a rejected settings change and a rejected approval answer. Those requests
settle and update their state, while the visible file tab gives no failure feedback. This
also affects **Pending setting changes**. The daemon still refuses a second answer under
**One answer per approval**. A new approval can also leave the session waiting without a
visible cue when the user is reading a file and has closed the session list. This affects
**Permission requests**.

### Places

`cmd/ox/web/src/App.tsx:203`–`:213` excludes the current draft from the page-level error.
`cmd/ox/web/src/NewSessionView.tsx:73` displays the local error in chat, which
`cmd/ox/web/src/TabArea.tsx:203` hides when a file is active.
`cmd/ox/web/src/SessionView.tsx:110` displays notices and errors for the session within the
same hidden chat. `cmd/ox/web/src/ox.tsx:470` and `:486` store settings and approval
failures in that control.

### Evidence

Reproduced in full-stack Chromium. The probe held create, opened the file, and released the
request with an unavailable model. The error existed in the hidden chat and became visible
after selecting the chat tab. The existing failure spec reopens a draft whose chat remains
active. The approvals reviewer reproduced a hidden error from a late answer in Chromium with
two pages. The settings reviewer reproduced the same failure path after a held configure.
The recovery notice uses the same chat view. A separate two-tab browser probe held a send,
switched to a file, closed the session list, and released the send. Selecting chat was the
first visible sign of the waiting approval.

### Origin

`e721130` (#144), [tabs and splits review](../reviews/2026-11-26-tabs-and-splits.md).

### Action

Keep chat request failures, recovery feedback and waiting approval status discoverable while
another tab is active. Provide a direct way back to recovered input or the approval. Cover
creation, settings and approvals.

[Issue #148](https://github.com/kkestell/ox/issues/148)

## F6. Changes rows omit line counts and large diffs count as zero

High · Requirements · Plan

The Changes sidebar shows file names and folders without the required counts. A text diff
over the display limit also contributes zero to the branch and tab totals, even though Git
knows its counts. This breaks **Changes view** and **Tabs**.

### Places

`cmd/ox/web/src/Changes.tsx:106` renders name and folder. `internal/server/changes.go:274`
reads numstat records and retains only paths. `cmd/ox/web/src/diff.ts:14` derives counts
from display hunks, which are dropped for oversized diffs.

### Evidence

The Files reviewer observed count-free rows in Chromium. A full-stack parent probe confirmed
`git diff --numstat` reported 65,000 additions and one deletion while Ox displayed +0 and −0
and the size warning. The sidebar spec at `cmd/ox/web/e2e/workspace.spec.ts:612` checks
names and totals without requiring per-file counts.

### Origin

`5dbd0b3` (#100), [Changes review](../reviews/2026-11-25-changes-view.md), discarded Git's
counts. `e721130` (#144), [tabs review](../reviews/2026-11-26-tabs-and-splits.md), moved the
separate file list into the sidebar.

### Action

Carry a file's counts independently of its displayable hunks. Use those counts in the rows,
summary, and tab. Cover an oversized tracked diff and the row counts through their public
entry points.

## F8. Claude's startup timeout runs long and can lose its final diagnostic

High · Process I/O · Plan

The startup limit starts process termination, and the failed prompt settles only after the
process exit and output drain. A process that takes time to exit can exceed the one-minute
**Failed startup** limit. A plain stdout diagnostic during termination can also disappear
from the timeout report.

### Places

`internal/claude/agent.go:152` assigns plain text based on startup phase, `:162` begins
termination, and `:376` assembles the timeout error from the original startup record and
stderr. `internal/claude/claude.go:165` allows ten more seconds to kill.
`internal/process/process.go:125` drains output after exit.

### Evidence

A stand-in with scaled 400 ms startup and 500 ms termination limits settled after 909 ms.
The exit retained stderr and omitted the later stdout diagnostic. The subsequent source
trace verified both ends of that path.

### Origin

`af75af3` (#141), [startup and Stop
review](../reviews/2026-11-26-claude-stopped-tools-and-startup-stderr.md).

### Action

Make the timeout's visible deadline and captured failure reason agree with the startup
contract. Keep prompt restoration and child cleanup coordinated with that result.

## F9. A failed first write to Ur leaves an empty child and blocks retry

High · Ownership · Plan

A Claude session can request an Ur child. If the process launches and closes its input
before accepting the first message, creation reports failure while an empty child remains in
the session list and database. Retrying with the same name is refused. This breaks **Claude
can start child sessions**.

### Places

`internal/server/mcp.go:431` stores the child, `:448` publishes it, and `:453` passes the
first message through the adapter. `internal/ur/agent.go:248` returns a pipe write failure
before recording the message.

### Evidence

The session collaboration reviewer used the production MCP handler and Ur adapter with a
stand-in that closed stdin. The call returned broken pipe, the child remained in
`workspace/list`, `session/get` had no first message, and a same-name retry reported an
existing child. The source has no rollback after publication.

### Origin

`ea7dd25` (#133) introduced a pipe write for accepting the first Ur input, [Ur process
review](../reviews/2026-11-26-run-ur-as-process.md).

### Action

Keep child creation owned by its creator until the first input is accepted. A refused first
input should leave no published child, reserved name or stored session.

## F11. A direct upgrade from an older database can prevent oxd from starting

High · Correctness · Plan

A database from before child sessions has session records without a directory field and no
children table. On direct upgrade, Ox creates the current children table, then tries to
remove the obsolete directory column from that table. Startup fails, leaving the saved
workspace and its sessions inaccessible. This breaks **Surviving restarts** for a user
upgrading from that schema.

### Places

`internal/store/store.go:92` defines the current children table without the old column.
`:164` creates missing tables before `:180` runs the migration, which unconditionally drops
`children.directory` at `:198`.

### Evidence

The input reviewer started production `oxd` with a scratch database initialized from the
tracked schema before `6a4e230`. It refused startup with a missing-column error. The parent
reproduced the same failure through race-enabled `store.Open` using that historical schema
and an existing workspace and session. `TestUpgradeAddsSessionDirectory` covers only the
intermediate schema that already has `children.directory`.

### Origin

`63277a0` (#83), [session directory review](../reviews/2026-11-24-session-directory.md).

### Action

Migrate according to the columns the database actually has, preserving the workspace
directory for older sessions and any saved child directory where available. Cover direct and
intermediate upgrades.
