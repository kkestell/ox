## F1. Child report delivery is triggered by updates, not derived from family state

High · Plan

Tracked in [#127](https://github.com/kkestell/ox/issues/127).

Whether a parent should receive its children's reports is a function of facts
`Server.mu` already guards: each child's published state and untaken reports,
the parent's state and archived flag, the family's membership, and whether
`oxd` is closing. Ox does not evaluate that function when those facts change.
It makes a report as a side effect of one child update, in `session.update`,
and tries delivery as a side effect of another, a state other than running or
parked, through `pingFamily`. Every path that changes the facts any other way
has to remember to make, drop, or deliver reports itself, and every update has
to arrive in the order delivery assumes.

The wrong states this permits:

- A family that is eligible with reports waiting, and nothing that will deliver
  them: unarchive changes eligibility without an update.
- A child that is not running while the report of the turn that just ended does
  not exist yet: a harness that publishes idle before the exit splits the
  family's reports into two deliveries.
- A child being deleted whose stop still makes and delivers a report: the stop
  runs through the ordinary update path before the session is marked deleting.
- A step that told the parent, marked on a later turn: the MCP handler reads the
  child's turn by a post after the call arrives.

### Places

- `internal/server/session.go:617` — `update` calls `report` for every update of
  a child, whatever caused it.
- `internal/server/session.go:620` — `update` tries delivery only on a state
  other than running, or parked.
- `internal/server/session.go:628` — `report` makes a report from a result or an
  exit, and moves the `told` state.
- `internal/server/session.go:668` — `pingFamily`, the only trigger for
  delivery.
- `internal/server/session.go:709` — `takeReports` evaluates eligibility, only
  when pinged.
- `internal/server/session.go:402` — `unarchiveLocked` makes the family eligible
  and triggers nothing.
- `internal/server/session.go:533` — `destroy` stops the agent before it sets
  `deleting`, so the stop's exit becomes a report and its parked state a ping.
- `internal/server/mcp.go:304` — `send_message` reads the caller's turn through
  a post, from another goroutine.

The Claude agent's `end` (`internal/claude/agent.go:420`) drops untaken inputs,
publishing idle, before it publishes the exit. It is where the ordering
assumption breaks, not a place of the structure.

### Defects

- [#71](https://github.com/kkestell/ox/issues/71): a late child message
  suppressed the next turn's report. #74 bound the mark to a turn, and left the
  handler reading the turn across goroutines. Guarded the symptom.
- [#85](https://github.com/kkestell/ox/issues/85): a report reached the parent
  while a sibling ran. #95 moved the reports under `Server.mu` beside the
  states, so eligibility and the take are one critical section. Changed the
  structure, for the take only.
- [Sweep F9](2026-11-25-ox-sweep.md#f9-unarchiving-leaves-a-childs-report-undelivered),
  in #110: unarchiving leaves a report undelivered. Open.
- [Sweep F10](2026-11-25-ox-sweep.md#f10-a-childs-failed-start-splits-its-siblings-reports),
  in #110: a child's failed start splits its siblings' reports. Open.
- [Sweep F11](2026-11-25-ox-sweep.md#f11-a-late-send_message-capture-suppresses-the-next-turns-report),
  in #110: a late capture suppresses the next turn's report, the window #74
  left. Open.
- Go and TypeScript review F3: deleting a running child delivers `Exited: Claude
  was stopped` to its parent, starting a parked parent's turn.
  `docs/protocol.md` ("Child reports") says such reports are dropped. No issue.
  Open.

Each fix proposed so far adds a trigger or a guard at one path: a delivery in
unarchive, an ordering in `end`, a `deleting` check in `report`.

### Evidence

A temporary race-enabled test through the JSON-RPC test client, with the fake
harness: a parent created a child whose first message was `wait 3000`, the test
waited for the child's `running` update and sent `session/destroy`. The parent
then took a prompt with one report, `Exited: stopped`, from the deleted child.
The test was removed. The sweep's reproductions of F9, F10, and F11 were traced
against the code at `6a94744`, which is unchanged in those paths.

### Replacement

Make delivery a function of the family's state, evaluated by the owner of that
state. Every fact it reads is already guarded by `Server.mu`, so every mutation
of those facts (a published state, a report, an archived flag, a child leaving
the family) goes through one step that, still holding the lock, checks the
affected parent and takes its batch when the family is eligible. The parent's
goroutine only accepts the batch. A child being deleted leaves the family's
facts when the delete starts, so neither its state nor its reports count, and
a report and the state that makes it deliverable are recorded together, so no
reading shows a child stopped without its report. The `told` mark moves onto the
child's goroutine, from the call's own `tool_use`.

This removes `pingFamily`, the trigger each path would otherwise add, and the
cross-goroutine turn read in `send_message`. It touches report creation and
delivery in `session.go` and `mcp.go`, possibly the ordering in the Claude
agent's `end`, and `TestChildReports`. Users see reports arrive in the cases
that now strand or split them, and no report from a deleted child. It resolves
#110.

## F2. A settings change in flight does not make a session busy

Low · Plan

Tracked in [#128](https://github.com/kkestell/ox/issues/128).

A session is reserved while a configuration runs: `docs/protocol.md`
(`session/configure`) says "Configuration reserves it until completion", and
**When settings can change** refuses changes to an archived session. The
harness knows a configuration is running; the Claude agent's phase is
`*configuring` and the fake's `config` is set. The server does not. `free`
reads only the published state, which stays `idle` during a configuration, so
the server and the harness decide by different rules whether the session can
be reserved.

The wrong state: a session archived while its configuration runs. The archive
stops the agent, the configuration ends with `ErrExited`, and the configure
callback adopts and stores the settings and broadcasts `session/configured`
after `session/archived`, a settings change to an archived session.

### Places

- `internal/server/session.go:325` — `free` reads the published state only.
- `internal/server/session.go:349` and `:382` — archive holds each member and
  itself by `free`.
- `internal/server/session.go:694` — report delivery checks `free`.
- `internal/server/methods.go:717` — the configure callback treats `ErrExited`
  as success and adopts the settings.
- `internal/claude/agent.go:301` — the Claude agent's own rule, `idle`, which
  counts the phase.
- `internal/fake/fake.go:152` — the fake's own rule, which counts `config`.

### Defects

Go and TypeScript review F2: `session/archive` succeeds during a configuration
and `session/configured` follows `session/archived`. Its proposed fix, a
`configuring` flag on the session, would keep the same fact in a second place.
No issue. Open.

### Evidence

A temporary race-enabled test through the JSON-RPC test client, with the fake
harness wrapped by the existing `configuringAgent`: an idle session got a
`session/configure` for its effort, and once the configuration had started, a
`session/archive` with no prompt queued. The archive succeeded, the
configuration succeeded, and the client received `session/archived` and then
`session/configured`. `TestArchive` covers only a configuration with a prompt
held behind it, which makes the published state `running`. The test was
removed.

### Replacement

Let the harness answer whether its session is free, from the state it already
holds, and have `free` take that answer instead of the published state. The
harness then keeps one rule for its own `Configure` and `Parkable` and for the
server's archive and delivery. It removes the gap between the two rules and
the need for a session-side flag. It touches `agent.Snapshot` or the `Agent`
interface, the three harnesses, `free`, and a case in `TestArchive`. An archive
during a configuration is then refused as busy, as the protocol says.

## F3. Claude's phase and its published state can disagree after a cancel

Low · Rejected

The Claude agent keeps its phase beside the tracker's reported state, and
`idle` needs both. The Go and TypeScript review's F4 says `commandCancelled`
can leave the phase `*prompting` while the tracker publishes idle, when Claude
cancels the only untaken prompt after reporting idle and sends no second idle.
The agent would then refuse configurations, never park, and report a stop as an
exit.

### Places

- `internal/claude/prompt.go:139` — `commandCancelled` drops the input and
  leaves the phase.
- `internal/claude/prompt.go:149` — `sessionState` releases the phase on idle
  with nothing untaken.
- `internal/claude/agent.go:301` — `idle` reads both.
- `internal/claude/park.go:8` — `Parkable` reads `idle`.

### Defects

None.

### Evidence

`docs/harnesses/claude-code.md` ("When a prompt is taken" and "Interrupt")
records that Claude reports `running` within milliseconds of receiving a
prompt, and that every cancel sequence, with or without `cancel_queued`, ends
with `idle` after `command_lifecycle cancelled`. That idle releases the phase.
The review's sequences need an idle while a written prompt is untaken, and no
recorded Claude output gives one.

### Replacement

Rejected as speculative. A live reproduction of the sequence would reopen it.

## F4. The page decodes every number by the tool-input rule

Low · Rejected

`connection.ts` parses every event with a reviver that keeps a number as raw
JSON when its source text differs from JavaScript's form of it, which
preserves large integers in tool inputs. The Go and TypeScript review's F6
says Go writes small floats such as `used_percent` as `5e-07`, which the
reviver would turn into an object that crashes the usage row.

### Places

- `cmd/ox/web/src/connection.ts:78` — the reviver.
- `cmd/ox/web/src/Usage.tsx:68` — rounds `used_percent`.

### Defects

None.

### Evidence

Go's `encoding/json` writes `1e-9*100` as `1e-7`, with the exponent's leading
zero removed, the same text JavaScript gives. The only remaining mismatch is
`-0`, which no field `oxd` sends can hold.

### Replacement

Rejected: the review misreads Go's encoder, and no value `oxd` sends reaches the
rule.
