# TUI review

## Scope and coverage

Reviewed the current interactive client in `crates/ox/src/tui.rs` and
`crates/ox/src/tui/`, the session operations it uses in `crates/ox/src/acp.rs`,
and the client and terminal tests. Lenses: correctness, resources, error
handling, testing, readability, simplicity, and Rust ownership. Traced input
editing, prompt submission, permissions, cancellation, session loading, picker
selection, transcript updates, rendering, and terminal cleanup. The bundled
server's prompt execution and a live terminal were outside this review.

The existing oversized approval layout finding, OX-0002, remains open and is not
repeated here.

## Findings

### High

#### Correctness

- **OX-0003: A second prompt silently replaces a queued prompt**
  (`crates/ox/src/acp.rs:137`): While a turn is busy, the first new prompt
  cancels that turn and occupies `queued`. Another Enter before the cancelled
  turn finishes overwrites that value. `send` has already taken both prompts
  from the composer (`crates/ox/src/tui.rs:971`), and only the last one is sent
  and shown when `finished` takes `queued`. The first prompt is lost. The
  existing test covers one queued prompt but not a second. Decide whether to
  retain multiple submitted prompts or keep subsequent text in the composer,
  then test two submissions during cancellation at the client boundary.

## Checks run

- Traced the busy submission path through `send`, `Session::prompt`,
  `Session::finished`, and the `Finished` event handler.
- Inspected the TUI and session tests for the same interaction.
- `make check-docs`: first reported two wrapping differences in this review;
  corrected them, then passed.
- `git diff --check`: passed.

## Verdict

One high severity input loss finding remains open. The existing approval layout
