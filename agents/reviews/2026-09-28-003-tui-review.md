## Fixed

- **Resume omitted user messages and joined separate answers**
  (`crates/ox/src/tui/transcript.rs:67`, high): `UserMessageChunk` updates fell
  through the ignored-update branch. Replaying two exchanges displayed
  `first answersecond answer` with neither question. The view now collects
  consecutive user chunks into user items, preserving questions and separating
  responses. Other updates end a user chunk sequence, including a title update
  from a turn with no answer.

## Findings

### Medium

#### Correctness

- **OX-0002 Tall approval blocks hide choices and the composer**
  (`crates/ox/src/tui.rs:352`): The frame reserves the approval's full height
  before placing the composer, then clips each region to the screen. A multiline
  shell command can put its last lines, both approval choices, and all input
  below the screen. Page Up and Page Down scroll only the transcript, so hidden
  command details cannot be inspected before Enter approves them. A temporary
  `TestBackend` reproduction with 24 `echo line` content lines at 80 by 24
  showed the heading and first 20 content lines; neither `1. Yes` nor the
  composer appeared. Reserve space for choices and the composer, bound the
  request details to the remaining height, and provide a way to scroll all
  details. This needs a layout and key-binding decision, so it remains open.
