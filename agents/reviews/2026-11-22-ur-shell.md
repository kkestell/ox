## F1. No test drops a stale command outcome during a later turn

Low · Testing · Fix · `internal/ur/ur.go:258`

`Handle` drops a `ran` unless `a.turn.step` is the step that started the command. That check matters when an interrupt kills a command and a new prompt starts the next turn before the killed command's outcome arrives. Without the check, the stale outcome would be saved as a tool entry and published as a `tool_result` in the new turn, and a second request would be posted alongside the new turn's request.

`TestShellInterrupt/executing` handles the late outcome while no turn is running, so the `a.turn == nil` half of the condition drops it on its own.

### Evidence

Changing the condition to `if a.turn == nil {` leaves `go test -race ./internal/ur/` passing.

### Action

In `TestShellInterrupt/executing`, send `p2` right after the interrupt, before handling the killed command's event. Then handle events until idle with `r.turn()`, and assert that no `tool_result` is published in the `p2` turn and that its request's roles are `user`, `assistant`, `tool`, `user`. Ur harness layer.

## F2. No test covers `WaitAll` waiting for a running command

Low · Testing · Fix · `internal/ur/shell.go:79`

*Stopping oxd* now covers Ur commands through `ur.WaitAll`, which counts command goroutines from `execute` until `runShell` returns. The wait is needed: `exec.CommandContext` runs `Cancel`, the group kill, on its own goroutine after the turn's context is canceled, so `oxd` could exit before the kill was sent. No test checks that `WaitAll` waits for a running command. Dropping `commands.Add`/`Done`, or the `ur.WaitAll()` call in `cmd/oxd/main.go`, fails nothing.

### Evidence

Traced `execute` → `runShell` and the shutdown path `s.Close()` → `claude.WaitAll()` → `ur.WaitAll()`. No test in `internal/ur` or `cmd/oxd` calls `WaitAll` or runs an Ur command through `oxd`, and `oxd` has no flag to point Ur at a canned endpoint.

### Action

Add a check to `TestShellStop/executing` at the Ur harness layer. While the command runs, call `WaitAll` on a goroutine and assert that it has not returned after about 100 ms. After `Stop`, assert that it returns promptly. The daemon-layer call stays a one-line wiring that the architecture doc describes. A test for it would need a new endpoint flag, which costs more than it protects.

## F3. No test covers a tool call without an id or name

Low · Testing · Fix · `internal/ur/stream.go:174`

`read` fails the turn with `OpenRouter sent a tool call without an id or name` when an assembled call lacks either field, as the plan's Wire format decision requires. No test reaches it.

### Evidence

Replacing the condition with `false` leaves `go test -race ./internal/ur/` passing.

### Action

Add a case to `TestStreamErrors`: a stream whose only tool-call fragment carries `index` and `function.arguments` but no `id` or name, then a `tool_calls` finish and `[DONE]`. Expect that error text, and `user`, `user` as the next request's roles.

## F4. A failing F1 test hangs on its blocked handler

Low · Testing · Rejected · `internal/ur/ur_test.go` (`TestShellInterrupt/executing`)

The canned handler for the second request blocks on `release` and ignores the request's context. If the subtest stops with `t.Fatal` before it reaches `close(release)`, for example on "the killed command delivered nothing", `httptest.Server.Close` in cleanup waits on that handler. The run then hangs until `go test` times out instead of failing at once.

### Evidence

Traced the subtest's `Fatal` paths against the cleanups that `start` and `launch` register. When the guard F1 protects is removed, the subtest fails through `t.Errorf` and still releases the handler. That run finished in 0.03 s.

### Action

Rejected: this only matters for a run that is already failing, and that run still reports a failure. Fixing it would cost another review round, which is more than it saves.
