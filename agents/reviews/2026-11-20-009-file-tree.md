## F1. Protocol says an absolute symlink to an inside folder is a folder

Low · Documentation · Fix · Resolved · `docs/protocol.md:158`

`docs/protocol.md` says "A symlink is a folder when it leads to a folder
inside the workspace's directory". But `os.Root` refuses every symlink with an
absolute target, even one that points inside the root. So an absolute link to
`<workspace>/src` is listed as a file, and listing it returns `-32000`
`statat abs: path escapes from parent`. The requirement still holds, since
nothing outside the workspace is listed, and the plan's Decision (folder means
`root.Stat` reports a directory) is what the code does. Only the protocol text
is wrong.

### Evidence

A probe with `os.OpenRoot` on a temporary directory holding `src/`,
`abs -> <dir>/src`, and `rel -> src` gave `abs false statat abs: path
escapes from parent` and `rel true <nil>`.

### Action

Correct the sentence in `docs/protocol.md` to say that a symlink is a folder
when its relative target leads to a folder inside the workspace's directory,
and that one with an absolute target, one that leads outside, or one that
leads nowhere is not. In `TestListFolder`, add an absolute symlink to `src`
with `folder` false, so the documented behavior is tested.

## F2. No test checks that a symlink to a file is a file

Low · Testing · Fix · Resolved · `internal/server/files.go:52`

`listFolder` sets a symlink's `folder` to `err == nil && info.IsDir()`.
`TestListFolder` has a link to a folder inside the workspace and a link
outside it, but no link to a file inside. So nothing tests the `IsDir` half.

### Evidence

Replacing the line with `isFolder = err == nil && info != nil` leaves
`TestListFolder` passing.

### Action

In `TestListFolder`, add a symlink to a file inside the workspace (for
example `notes -> .gitignore`) and expect `folder` false in the root listing.

## F3. Workspace name derived separately by sidebar and file tree

Low · Construction · Fix · Resolved · `cmd/ox/web/src/FileTree.tsx:36`

The panel header shows the workspace folder's name "in the style of the
sidebar's workspace headings". `FileTree.tsx:36` and `Sidebar.tsx:81` each
compute that name with the same expression,
`path.split("/").at(-1) || path`. If either changes, for example to handle a
trailing slash, the panel header and the sidebar heading will name the same
workspace differently.

### Evidence

Read from the source.

### Action

Define the name in one function, for example `workspaceName(path)` exported
from `ox.tsx`, and call it from both components. No new test is needed: the
e2e test's check of the header text (`basename(other)`) covers it.

## F4. A folder expanded while disconnected stays blank

Low · Correctness · Rejected · —

`Folder` lists itself on mount without checking `ox.ready()`. Expanding a
folder while the connection is lost sends a request. The connection rejects
it without an `RpcError`, so the folder shows no rows until the first tick
after the reload.

### Evidence

Traced through `FileTree.tsx` (`list`, `createEffect`) and the interval's
`ready` check.

### Action

Rejected: the plan intends this. A connection failure leaves the last
listing, the page already reports the lost connection, and listing resumes
within a second of the reload. The one extra request is rejected immediately.
