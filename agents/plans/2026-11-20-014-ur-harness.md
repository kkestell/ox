# Ur: a built-in OpenRouter chat harness

## Goal

Ox offers a second real harness, Ur, beside Claude. Ur runs no process: each
turn POSTs the session's conversation to OpenRouter's chat completions API
with `stream: true` and streams the reply into the transcript. This first
slice is multi-turn text chat with no tools. History lives in the agent's
memory, so an Ur session never parks on its own.

## Decisions

- **Package and constructor.** New package `internal/ur`, depending only on
  `internal/agent` and the standard library. `ur.Harness(endpoint string,
  providers map[string][]string) agent.Harness` returns `{Start, CheckPrompt:
  nil}`; `ur.Endpoint` is
  `https://openrouter.ai/api/v1/chat/completions`. Tests pass an
  `httptest.Server` URL. `cmd/oxd` registers `"ur": ur.Harness(ur.Endpoint,
  cfg.Harnesses["ur"].Providers())`.
- **Provider order is a property of the configured model.** `config.Model`
  gains `Providers []string \`json:"providers,omitempty"\``. The request body
  is built from the session's model ID, and the order that makes a model's
  latency, cost, and effort handling predictable belongs with that model in
  the catalog, which the user can edit. `config.Harness.Providers()` returns
  model ID → order for models that set one. A model with an order sends
  `"provider": {"order": [...], "allow_fallbacks": false}`; one without sends
  no `provider` and OpenRouter routes freely. `harness/list` serves the field
  as part of the catalog; the web client ignores it.
- **Built-in catalog.** `default.json` adds harness `ur` with permission mode
  `{"id": "manual", "name": "Manual"}` and three models, each with the effort
  levels OpenRouter lists for it (besides `none`):
  - `deepseek/deepseek-v4.1-flash-1017`, `DeepSeek V4.1 Flash`, efforts
    `low`/`high`/`max`, `providers: ["inference-net/us", "stepfun/fp8"]`.
  - `z-ai/glm-5.3-flash`, `GLM 5.3 Flash`, efforts `low`/`high`/`max`,
    `providers: ["cohere/nvfp4", "deepinfra/fp4"]`.
  - `meta/muse-spark-1.3-contributor`, `Muse Spark 1.3 Contributor`, efforts
    `minimal`/`low`/`medium`/`high`/`xhigh`/`max`, `providers: ["meta"]`.

  Defaults stay Claude Haiku.
- **Permission mode.** Ur takes exactly `manual`: with no tools, every tool
  call asking first holds vacuously, and the name stays correct when tools
  arrive. Ur ignores the field, so any other mode would be silently ignored;
  `checkConfig` refuses it.
- **Effort.** `effort` maps to `"reasoning": {"effort": <id>}`; an empty
  effort omits `reasoning`. `ur.CheckEffort` accepts OpenRouter's values:
  `max`, `xhigh`, `high`, `medium`, `low`, `minimal`, `none`.
- **Config checks.** `checkConfig` for `ur`: every permission mode passes
  `ur.CheckPermissionMode` (only `manual`), every effort passes
  `ur.CheckEffort`. For any other harness, a model with `providers` is
  refused (`providers` is only for ur), since Claude would ignore it.
- **API key.** `Start` reads `OPENROUTER_API_KEY`; empty or unset returns
  `errors.New("OPENROUTER_API_KEY is not set")`, which `session/send` returns
  as its error through the existing launch-failure path. `oxd` starts without
  the key, so the built-in catalog works for users without OpenRouter.
- **Loading the key.** The `Makefile` loads `.env` with `-include .env` and
  exports only `OPENROUTER_API_KEY`, so `make dev` and `make live` both pass it
  to `oxd` and tests. `.env` also holds an OpenRouter management key, which
  stays out of every process environment. `.gitignore` gains `/.env`.
- **Agent state.** All fields are owned by the session goroutine:
  - `settings agent.Settings`, `history []message` (`{Role, Content}`),
    `queue []agent.Input`, `exited bool`.
  - `turn *turn`, nil while idle: `{prompt string, cancel
    context.CancelFunc, reply strings.Builder}`. Running is `turn != nil`;
    there is no separate state field. `Snapshot().State` is `running` when a
    turn exists, else `idle`.
- **Turn lifecycle.**
  - `Send` appends to `queue`, publishes `prompt_queued`, and calls `begin`
    when `turn == nil`.
  - `begin` pops the first input, sets `turn`, publishes `prompt` and
    `state: running`, appends `{user, input.Content}` to `history`, marshals
    the request body on the session goroutine, and starts `stream(ctx, t,
    body)`.
  - An input sent during a turn waits in the queue and begins when the turn
    ends. A turn is one request, so there is no step at which to take it
    earlier.
  - `Handle(delta{t, text})` with `t == a.turn` appends to `reply` and
    publishes `text_delta`. `Handle(ended{t, err})` with `t == a.turn` calls
    `finish`. An event whose `t` is not the current turn belongs to an
    interrupted one and is ignored.
  - `finish(result)` appends `{assistant, reply}` to `history` when `reply` is
    non-empty, publishes `result` (the reply text, or the error text with
    `is_error`), then `state: idle` under the turn's prompt ID, clears
    `turn`, and calls `begin` if the queue is non-empty.
  - `Interrupt` with a turn: `cancel()`, `drop()` (each input
    `prompt_cancelled`), `finish({Text: "Interrupted", IsError: true})`.
    Without a turn it only drops. The partial reply stays in `history`, as
    the user saw it; consecutive user messages after a failed turn are
    accepted by chat completions.
  - `Stop`: cancel any turn, `drop()`, publish `exited` with `stopped` when a
    turn was running, set `exited`, close `done`.
  - `Configure`: `ErrBusy` while a turn exists; otherwise apply the patch,
    call `OnConfigured` when the settings changed, `done(nil)`.
  - `Approve` returns `agent.ErrApprovalNotFound`. `Parkable` returns false.
    `OnResumable` is never called.
- **Request.** POST with `Authorization: Bearer <key>` and `Content-Type:
  application/json`. Body: `model`, `messages` (the history), `stream: true`,
  plus `reasoning` and `provider` as above. Uses `http.DefaultClient`.
- **Stream reader** (`stream`, the request goroutine). It reads only the
  response and delivers `delta` and `ended` through `events`, each send
  selecting on `done`. It touches no agent field; `t` is only an identity.
  - A non-200 status reads at most 64 KiB of body and ends with `OpenRouter
    <status>: <error.message>`, or the status alone when the body has no
    message.
  - A 200 is read with `bufio.Reader.ReadString('\n')`, processing a final
    line that ends at EOF. Blank lines and `:` comments (OpenRouter's
    `: OPENROUTER PROCESSING` keep-alives) are skipped. `data: ` lines are
    parsed. A chunk with `error` ends with `OpenRouter: <message>`, which
    covers the mid-stream errors OpenRouter sends under a 200. Non-empty
    `choices[0].delta.content` becomes a `delta`. `delta.reasoning` is not
    shown in this slice. A non-empty `finish_reason` marks the reply
    finished; reading continues past the usage chunk to `data: [DONE]` or
    EOF.
  - At `[DONE]` or EOF, a finished reply ends without error; otherwise it
    ends with `OpenRouter stream ended before the response finished`. A
    transport error ends with that error, and is ignored when the turn was
    cancelled.
  - Malformed chunk JSON ends with `malformed OpenRouter stream chunk: <err>`.
- **Requirements.** *Stop*: `Interrupt` ends the turn at once with an
  interrupted result and drops pending inputs, and their text returns to the
  composer through the existing `prompt_cancelled` path. *Failed turns*: HTTP
  and stream errors end the turn with an error `result`. *Replies as
  Markdown*: `text_delta`. *One prompt at a time*: a prompt sent mid-turn
  shows pending and runs next. *Settings shown are settings used* and
  *Setting changes keep the rest*: `Configure` applies at once and the next
  request reads `settings`; history is untouched. *Message delivery*: a
  message's `Content` is the user message. *Surviving restarts*: the
  transcript survives through the server's history; the conversation context
  does not (see Check your assumptions). *Parking*: Ur never reports
  parkable; after an `oxd` restart or unarchive, an Ur session is parked like
  any other and its next send starts a fresh agent. *Built-in catalog* and
  *Configuration checks* change; see Requirement changes. A page's lost reply,
  reconnect, or second page behave as for any harness: Ur publishes through
  the same updates and snapshot.
- **Settling.** The one new wait is the HTTP response. It ends with the
  stream (`[DONE]`, EOF, an error chunk), with `Interrupt` or `Stop`
  cancelling the context, or with a dead connection, which Go's default
  dialer's TCP keep-alive detects. A live but silent server is not a case:
  OpenRouter sends keep-alive comments while it waits. Every path delivers
  `ended`, so every turn publishes a `result`.
- **Construction.** "Running" and "has a reply and a cancel func" are one
  value, `turn`, which exists only while a turn runs. The request goroutine
  receives marshalled bytes and holds no reference to `history` or
  `settings`. Stale events are recognized by turn identity, with no
  generation counter. Valid efforts and permission modes are checked once,
  at config load; Ur relies on them.
- **Ownership.** `history`, `queue`, `turn`, and `settings` are owned by the
  session goroutine, via the agent. The user-visible behavior that needs
  `history` is multi-turn chat. Its cleanup is the agent's end; losing it on
  `Stop` is why `Parkable` is false. The request goroutine owns nothing it
  shares. Its race with `Interrupt` (a delta in flight after cancel) is
  resolved by the turn identity check. Its race with `Stop` is resolved by
  `done`. The commit body repeats this.
- **Trust boundaries.** `oxd` now holds `OPENROUTER_API_KEY` in its
  environment, and Claude processes inherit it as they inherit the rest of
  `oxd`'s environment. The key is sent only to `ur.Endpoint`. The
  management key in `.env` is never exported.

## Check your assumptions

1. **An Ur conversation forgets its context after an `oxd` restart or archiving.**
   - **Plan:** The transcript stays, but after `oxd` restarts, or the session
     is archived and unarchived, the next prompt starts a new conversation
     with no notice. The model no longer knows the earlier turns. Ur sessions
     never park when idle, so this happens only on those two events. Storing
     history comes in the next slice.
   - **Alternative:** Ur shows the same notice Claude shows when it cannot
     resume. The first prompt after a restart is dropped with "could not
     resume the earlier conversation" and its text returns to the composer.
     This costs a placeholder resume token and a lost-conversation path in Ur
     that the next slice would delete.
2. **Ur offers DeepSeek V4.1 Flash, GLM 5.3 Flash, and Muse Spark 1.3
   Contributor.**
   - **Plan:** The model picker lists the three models under Ur, each pinned
     to providers measured at about 0.3–0.7s per short reply (Muse Spark,
     which always reasons, 1.4–3s on its only provider, Meta). New sessions
     still default to Claude Haiku. Ur's permission menu shows the single
     choice Manual.

## Test plan

- New `internal/ur/ur_test.go`. Each test starts the agent with
  `ur.Harness(server.URL, providers).Start` against an `httptest.Server`
  serving canned SSE, sets `OPENROUTER_API_KEY` with `t.Setenv`, and drives
  it from the test goroutine: call methods, pass `Events()` to `Handle`, and
  record `OnUpdate`. No existing test reaches a new package.
  - Two turns: the update sequence is `prompt_queued`, `prompt`, `state
    running`, `text_delta`…, `result` with the joined text, `state idle`,
    each carrying the prompt's `message_id`. The second request's body has
    `model`, `stream: true`, `reasoning.effort`, `provider.order` with
    `allow_fallbacks: false`, the `Authorization` header, and messages
    user/assistant/user. A model with no providers sends no `provider`, and
    an empty effort sends no `reasoning`.
  - The final `data: [DONE]` line has no trailing newline and still ends the
    turn without error.
  - A mid-stream `error` chunk under a 200 ends with an error `result`
    carrying its message, then `state idle`.
  - A 4xx with an OpenRouter error body ends with an error `result` carrying
    the status and message.
  - A stream that ends before any `finish_reason` ends with an error
    `result`.
  - Interrupt: the handler streams one delta, then blocks on the request
    context. After the delta, `Send` queues a second input. `Interrupt`
    publishes `prompt_cancelled` for it, an `Interrupted` error `result`, and
    `state idle`. A later `Send` posts a history that holds the partial
    reply. No update follows the interrupt from the old stream.
  - An input sent mid-turn runs as the next request after `result`.
  - `Configure` while running returns `ErrBusy`. While idle it calls
    `OnConfigured` with the new settings, and the next request uses the new
    model and effort.
  - `Start` without `OPENROUTER_API_KEY` returns an error naming it.
  - `Stop` mid-turn publishes `exited` and `Exited()` reports true.
- `cmd/oxd/main_test.go`, in the existing `checkConfig` test, with `ur`
  in the harness map: the built-in config passes. A ur effort `"extreme"`, a
  ur permission mode `"auto"`, and `providers` on a claude model are each
  refused.
- `internal/config/config_test.go`, in `TestCatalogListsArePresent` or
  beside it: `Providers()` returns the order for a model that sets one and
  omits a model that does not.
- Live, new `TestLiveUr` in `internal/server/live_test.go` (`-run TestLive`
  matches it). It skips without `OX_LIVE` and fails clearly without
  `OPENROUTER_API_KEY`. It loads the built-in config and serves `{"ur":
  ur.Harness(ur.Endpoint, cfg.Harnesses["ur"].Providers())}` through `New`
  and the protocol client. It creates an Ur session with
  `deepseek/deepseek-v4.1-flash-1017` at effort `low`, sends "Remember the
  number 7341. Reply with just the word ok.", and waits for `text_delta`, a
  non-error `result`, and `state idle`. It then sends "What number did I ask
  you to remember? Reply with just the number." and checks that the result
  contains `7341`. A separate test is needed because `TestLive` builds a
  Claude-only server.
- Web: no new spec. The icon and name are a static lookup that the
  existing picker renders. Check the picker in headless Chrome through the
  `make dev` stack.

## Requirement changes

- **Added:** **Ur sessions.** Ur chats through OpenRouter with the user's `OPENROUTER_API_KEY`, streaming text replies with no tools; a send to an Ur session without the key is refused with an error. An Ur session never parks while `oxd` runs, and after an `oxd` restart or unarchiving it keeps its transcript, but its next prompt starts a new conversation without the earlier context.
- **Changed:** **Built-in catalog.**
  - Old: Without a configuration file, Ox offers Claude Opus, Sonnet, and Haiku 5.5 with their effort levels and the manual, auto, acceptEdits, and plan modes.
  - New: Without a configuration file, Ox offers Claude Opus, Sonnet, and Haiku 5.5 with their effort levels and the manual, auto, acceptEdits, and plan modes, and Ur with DeepSeek V4.1 Flash and GLM 5.3 Flash at low, high, and max effort and Muse Spark 1.3 Contributor at minimal, low, medium, high, xhigh, and max effort, in manual mode.
- **Changed:** **Configuration checks.**
  - Old: `oxd` refuses to start with a malformed configuration, defaults it does not offer, an unknown harness, or an effort level Claude does not take, and says why.
  - New: `oxd` refuses to start with a malformed configuration, defaults it does not offer, an unknown harness, or an effort level, permission mode, or provider order its harness does not take, and says why.
