# Rewrite the TUI with ratatui

## Goal

Replace the scrollback-based terminal output in `crates/ox` with a full-screen
ratatui interface made of two parts: the transcript view above and the composer
below. The transcript view shows user messages, thinking, tool calls, responses,
and notices, auto-scrolls to new items, and can be paged manually. The composer
is a multi-line input with a status line that shows the session settings and
usage. The input stays usable while a turn runs: sending a message interrupts
the turn.

At 72 columns, a session in Ask mode looks like this while a shell command
awaits approval:

```text
❯ Run the tests!

Thought for 12s

• Read Makefile
• Find files matching *.rs

$ ls -la

Two tallies were counted in the workspace.

────────────────────────────────────────────────────────────────────────

Would you like to run the following command?

$ rg -n \
  --glob '*.rs' \
  'TODO|FIXME' src

› 1. Yes
  2. No

────────────────────────────────────────────────────────────────────────
❯ Also check the docs
  when you are done
────────────────────────────────────────────────────────────────────────
ask • deepseek/deepseek-v4-flash • high                        5% • $0.01
```

Once approved, the command appears in the transcript view as a `$` block and the
approval block disappears. While the transcript view is scrolled up and new
items arrive, its last row shows `new activity` centered in bright yellow.

## Related code

- `crates/ox/src/tui.rs`: the current terminal code. `Output` streams ACP
  updates into scrollback text, `Terminal` writes it and redraws a one-line
  input, `run` is the event loop. All of it is replaced.
- `crates/ox/src/acp.rs`: `Session` owns `pending` permission requests, `busy`,
  and `cancelling`; `run` drops the `config_options` in the
  `NewSessionResponse`. `Event` carries updates, permission requests, turn
  results, and diagnostics.
- `crates/ox/tests/tui.rs`: the tmux tests. They read scrollback with
  `capture-pane -S -`, wait for the startup help line, and use `C-c` to cancel.
  All of them change.
- `crates/ox-fake-server/src/lib.rs`: `Script::render`, `Script::ask`,
  `Script::options`, and `Script::usage` supply deterministic updates for the
  terminal tests.
- `crates/ox-acp/src/acp/convert.rs`: `shell_permission_request` names the
  options `Approve` and `Deny`, and scopes a subagent's request by prefixing its
  tool call ID and tool call title. `agent_message_updates` sends subagent
  answers as finished tool calls without a raw tool name.
- `crates/ox-acp/src/acp/prompt.rs`: `execute` announces every tool call of a
  batch as `Pending` before running them one at a time, so a pending call is one
  that has not started yet.
- `crates/ox-acp/src/tools.rs`: `tool_call_title` already produces the one-line
  previews the transcript view shows, such as `Read foo/bar.md` and
  `Apply patch`.
- Follow `AGENTS.md`, `agents/architecture.md`, `agents/code-style.md`,
  `agents/glossary.md`, and `agents/testing.md`.

## Decisions

### Terminal

- Use ratatui 0.30 with its crossterm backend and the alternate screen. Add
  `ratatui = "0.30"` to the workspace dependencies. Keep the direct `crossterm`
  dependency for `EventStream`, and confirm with `cargo tree -d` that only
  crossterm 0.29 is present, enabling ratatui's `crossterm_0_29` feature if it
  is not.
- Set the terminal up and restore it in `tui.rs`, not with `ratatui::init`,
  because bracketed paste, focus events, and the keyboard enhancement flags must
  be enabled and disabled too. The panic hook restores the terminal as today.
- Push crossterm's `DISAMBIGUATE_ESCAPE_CODES` keyboard enhancement flag when
  `supports_keyboard_enhancement()` is true. This is what lets the terminal
  report Shift+Enter separately from Enter. In a terminal without it,
  Shift+Enter sends the message. Query support before creating the
  `EventStream`.
- Redraw the whole frame after every event. Before drawing, drain every ACP
  event that is already waiting so a burst of streamed chunks costs one draw.
- Tick once per second with `tokio::time::interval` so thinking placeholders
  count up. The tick only redraws.
- Keep the pane title and the bell when the terminal is unfocused. Drop the
  startup help line, `Turn finished`, and `Cancelling…`.

### Transcript view

- Keep every item in memory and render all of them to lines at the current width
  on each draw. Wrapping is a pure function of the full text, so the streaming
  word buffer in the current `Message` goes away.
- Items: `User`, `Thinking`, `Response`, `Tool`, and `Notice`. Consecutive agent
  message chunks extend one `Response`; consecutive thought chunks extend one
  `Thinking`. Any other update, a permission request, or the end of the turn
  ends the open `Thinking` and records its end time.
- One blank row separates items, except between two adjacent one-line `•` tool
  calls. A `$` block always has blank rows around it.
- Word-wrap `User`, `Thinking`, and `Response` text by display width. Trim
  leading and trailing whitespace from the whole text, keep interior blank
  lines, expand tabs, split words wider than a line, and escape control
  characters. `User` lines start with `❯` and continue with two spaces. Text is
  default color except `Thinking`, which is `DarkGray`.
- `Thinking` shows `Thinking...` until 10 seconds have passed, then
  `Thinking for 12s...` counting each second, then `Thought for 42s` once ended.
  Ctrl+T toggles one flag that shows the reasoning text for every `Thinking`
  item instead of its placeholder; an item whose text is still empty keeps the
  placeholder.
- A tool call with a raw tool name other than `shell` is one line: a status icon
  `•`, a space, and its tool call title, clipped to the width with `…`. The icon
  is `Indexed(208)` (orange) while `Pending`, `Red` when `Failed`, and default
  otherwise. A tool call without a raw tool name, such as a subagent answer,
  shows the same line followed by its text content word-wrapped, indented two
  spaces, in `DarkGray`.
- A tool call named `shell` renders as a `$` block: `$` before the first line of
  `raw_input.command` and two spaces before each further line, so the command's
  own indentation is kept. Lines wider than the view wrap with a two-space
  hanging indent. When `raw_input.background` is true, `&` follows the last
  line. The `$` is the status icon and takes the same colors. The block is not
  shown while the call is `Pending`; it appears when the call starts, or when it
  is denied or cancelled, which the server reports as `Failed`.
- Proposed display for shell processes: `shell_process` calls are ordinary
  one-line tool calls using their tool call titles, such as
  `• Read shell process p-1` and `• Write to shell process p-1`. The text being
  sent is shown only in the approval block, from the request's content.
- Proposed display for subagents: `start_subagent`, `send_message`,
  `stop_subagent`, and `wait` are one-line tool calls using their tool call
  titles. A subagent's answer or failure is the nameless tool call described
  above: `• Final answer from subagent child-1` or
  `• Failure of subagent child-1`, followed by its text in gray; a failure has a
  red icon. A subagent's shell approval names the subagent in its heading; see
  the approval block below.
- A turn error is a `Notice` in `Red`: `Turn error: <message>`. A server stderr
  line is a `Notice` in `DarkGray`. A finished or cancelled turn adds nothing.
- Auto-scroll: the view shows its last lines. Page Up sets a manual top row one
  page above; Page Down moves one page down and, on reaching the bottom,
  restores auto-scroll; End restores it directly. A page is the view height less
  one row. Any change to the items or a newly displayed approval while
  auto-scroll is off sets the new activity flag, which draws `new activity`
  centered in `LightYellow` over the view's last row. Restoring auto-scroll
  clears it.

### Approval block

- The approval block renders the front of `Session::pending` between the
  transcript view and the composer, at its natural height: a rule, a blank row,
  a heading, a blank row, the request, a blank row, the options, and a blank
  row. The composer's top border closes it. Its request state is the known tool
  call merged with the request's fields, as `Output::permission` does today.
- For a request named `shell`, the heading is
  `Would you like to run the following command?` and the request is the `$`
  block, including `&` for a background command. When the request's tool call
  carries `_meta.subagent_id`, the heading is
  `Subagent child-1 would like to run the following command.`
- For any other request, the heading is `Would you like to allow the following?`
  and the request is the `•` line followed by the request content word-wrapped
  and indented two spaces. This is how sending input to a shell process is
  approved: the content from ox-acp already lists the process, its command, and
  the input text.
- Options are numbered from 1 and show the server's option names. `›` marks the
  selected option, which starts at the first. Up and Down move it. Enter answers
  with it when the input is empty. Escape answers with the first option whose
  kind is `RejectOnce` or `RejectAlways`, else the last option. Number keys are
  labels only, so typing into the input during an approval never answers it.
- Rename ox-acp's shell permission options to `Yes` and `No`. The option IDs
  `approve` and `deny` do not change.
- Set `_meta.subagent_id` on the permission request's `ToolCallUpdate` in
  `shell_permission_request` when the request comes from a subagent.

### Composer

- The composer is the bottom of the frame: a rule, one to eight input rows, a
  rule, and the status line. The input rows are the input's visual rows, clamped
  to that range, so the composer grows with the text and scrolls once it reaches
  eight rows, keeping the cursor row visible.
- `Input` holds the text and a byte cursor. It supports inserting a character,
  inserting pasted text with `\r\n` and `\r` normalized to `\n`, Shift+Enter
  newline, Backspace, Delete, Left, Right, Home, End, Up and Down between
  logical lines keeping the display column, and Ctrl+U to clear. Each logical
  line is hard-wrapped by display width into visual rows; the first visual row
  starts with `❯`, the rest with two spaces. Tabs display as `→` and other
  control characters as their escapes, and the cursor column is computed on the
  displayed text.
- Enter with non-empty text sends it. If a turn is running, `Session::prompt`
  stores the text as the queued prompt and cancels the turn; when the turn
  finishes, `Session::finished` sends the queued prompt and returns its text so
  the transcript view adds the `User` item then, after the cancelled turn's last
  output. The input clears as soon as Enter is pressed. Enter with empty text
  does nothing unless an approval is shown.
- Escape with an approval shown answers it as above. Otherwise, while a turn
  runs, Escape cancels the turn. Otherwise it does nothing.
- Ctrl+C and Ctrl+D cancel any running turn and quit.
- The status line shows `mode • model • effort` on the left and `used% • $cost`
  on the right. The left values are the `current_value` IDs of the session's
  config options with the categories `Mode`, `Model`, and `ThoughtLevel`, in
  that order, omitting any that is absent. `Session` keeps the `config_options`
  from the `NewSessionResponse` and replaces them on a `ConfigOptionUpdate`.
  `Session` also keeps the latest `UsageUpdate`; the percentage is
  `used * 100 / size` rounded, the cost is the amount with two decimals, and
  before any usage update the right side reads `0% • $0.00`. The currency is
  assumed to be USD.

### Code layout

- `crates/ox/src/tui.rs`: terminal setup and restore, the event loop, key
  handling, frame layout, the approval block, the composer chrome, and the
  status line. `escape` stays here for `main.rs`.
- `crates/ox/src/tui/transcript.rs`: `TranscriptView`, `Item`, how updates
  become items, scrolling, wrapping, and rendering items to lines.
- `crates/ox/src/tui/input.rs`: `Input`.
- Drawing takes a `Screen` of borrowed parts: the transcript view, the input,
  the approval to show with its selected index, the status line values, the
  thinking flag, and the current time. Tests build a `Screen` directly and draw
  it into ratatui's `TestBackend`.

## Naming

- **Transcript view**: the client's display of the session's transcript, the
  region above the composer. The glossary's transcript stays the durable record
  owned by the server. Code: `TranscriptView` in `tui/transcript.rs`.
- **Item**: one element of the transcript view: a user message, thinking, a tool
  call, a response, or a notice. Code: `Item`.
- **Thinking**: the transcript view's label for visible reasoning. Code:
  `Item::Thinking`; the placeholders are `Thinking...`, `Thinking for 12s...`,
  and `Thought for 42s`.
- **Notice**: a transcript view item that is neither the user's nor the agent's:
  a turn error or a server stderr line. Code: `Item::Notice`.
- **Composer**: the bottom region: a rule, the input rows, a rule, and the
  status line.
- **Input**: the editable text and cursor inside the composer. Code: `Input` in
  `tui/input.rs`.
- **Status line**: the composer's last row, with the session settings on the
  left and usage on the right.
- **Approval**: the block that shows one pending ACP permission request and its
  options. Code: `Approval`.
- **Auto-scroll**: the transcript view keeping its last lines visible. Paging
  turns it off; End or paging to the bottom turns it on.
- **New activity notice**: the bright yellow `new activity` row drawn over the
  transcript view's last row when items or approvals changed while auto-scroll
  was off.
- **Queued prompt**: the text sent by Enter during a turn, held in `Session`
  until the cancelled turn finishes. Code: `Session::queued`.

## Test plan

Unit tests in `crates/ox/src/tui/transcript.rs`:

- Wrapped text is trimmed and wrapped by display width: a table over the current
  cases (surrounding whitespace, whitespace only, interior blank lines, explicit
  newlines, tabs, word wrap, long words, wide characters, escaped control
  characters, the `❯` prefix and two-space indent).
- Chunks of one kind join one item, a chunk of another kind starts a new item,
  and the next item or the end of the turn ends the open thinking item.
- Thinking shows placeholders by elapsed time unless toggled: `Thinking...`,
  `Thinking for 12s...`, `Thought for 42s`, and the text with the flag on, with
  injected times.
- Items render with icons, prefixes, and spacing: a table over item sequences
  and their rows at a fixed width, covering the one-line tool call, clipping
  with `…`, the nameless tool call with gray content, notices, and blank-row
  placement including adjacent `•` lines and a `$` block.
- Shell calls stay hidden while pending and render as `$` blocks: multi-line
  indentation, `&` for background, the failed call in red, and no rows while
  pending.
- The tool status sets the icon color: orange pending, red failed, default
  otherwise.
- Paging turns auto-scroll off and End or the bottom turns it on, and the new
  activity flag is set by changes while off and cleared when on.

Unit tests in `crates/ox/src/tui/input.rs`:

- Editing keys move the cursor and change the text, including Up and Down
  between logical lines and Ctrl+U.
- Paste normalizes line endings and waits for Enter.
- Rows wrap at the width and keep the cursor visible: the row count clamps to
  one through eight, the cursor row and column are computed on displayed text,
  and the scroll offset follows the cursor.

Unit tests in `crates/ox/src/tui.rs` with `TestBackend`, at 72 by 24:

- The frame places the transcript view, the approval block, the composer, and
  the status line as in the Goal, with the cursor on the input.
- The new activity notice covers the view's last row and only while auto-scroll
  is off.
- The status line shows settings on the left and usage on the right, omits an
  absent category, and reads `0% • $0.00` before usage arrives.
- Approval keys: Up and Down move the selection, Escape picks the reject option,
  and Enter answers only when the input is empty. Test these on the key-handling
  function with a `Session` from the fake server, as the ACP tests in `acp.rs`
  do.

Unit test in `crates/ox/src/acp.rs`:

- A prompt during a turn cancels it and is sent after it finishes: `prompt`
  while busy stores the queued prompt and sends a cancel, `finished` sends it
  and returns its text, and the fake server's second reply names it.

Unit tests in `crates/ox-acp/src/acp/convert.rs` and `crates/ox-acp/src/acp.rs`:

- Update the permission option names to `Yes` and `No` where asserted.
- A subagent's shell permission request carries `_meta.subagent_id`, and the
  main agent's does not.

Terminal tests in `crates/ox/tests/tui.rs`, run by `make e2e`, capturing the
current screen instead of scrollback and waiting for the status line at startup:

- Keys send, interrupt, approve, scroll, and restore the shell: `stream`
  appears; `tool` shows the approval heading and the option names, Down then
  Enter answers `selected stop`, Enter answers `selected go`; `running` then
  Escape shows `cancelled`; `running` then a typed message with Enter shows the
  message's reply after `cancelled`; Shift+Enter adds a second input row; a
  paste with a newline shows two rows and sends as one prompt; Page Up during a
  long reply shows `new activity` and End clears it; Ctrl+D leaves the alternate
  screen and the shell script prints `TERMINAL_RESTORED` and `EXIT_0`. The tmux
  configuration sets `extended-keys on` so `S-Enter` reaches the program.
- The transcript view renders thinking, tools, and wrapped replies at 40 columns
  from the `render` script: the gray `Thought for 0s` placeholder, the `$ ls`
  block, `• Read tallies/…` clipped to one line, the `$ npm run dev &` block,
  the subagent answer with gray content, and the wrapped response, as physical
  rows and with ANSI attributes.
- The status line shows the `options` values and `15% • $0.25` after the `usage`
  script.
- Keep the disconnect, server failure, and pane title tests, changing their
  waits to the new approval text and option names.
- Keep the invalid startup test unchanged.

## Implementation plan

1. Add `ratatui` to the workspace and to `crates/ox/Cargo.toml`. Confirm one
   crossterm version.
2. In `crates/ox/src/acp.rs`, add `config_options`, `usage`, and `queued` to
   `Session`; keep the `NewSessionResponse` config options; make `prompt` queue
   and cancel during a turn and `finished` send the queued prompt and return its
   text. Add the queued prompt test.
3. Create `crates/ox/src/tui/transcript.rs` with wrapping, `Item`,
   `TranscriptView` update handling, scrolling, and rendering to lines. Port the
   current wrapping cases and add the tests above.
4. Create `crates/ox/src/tui/input.rs` with `Input`, its editing operations, and
   row rendering with cursor position. Add its tests.
5. Rewrite `crates/ox/src/tui.rs`: terminal setup and restore, `Screen` and
   drawing with the approval block, composer, status line, and new activity
   notice, the key handling, and the event loop with the one-second tick and
   event draining. Add the `TestBackend` and key-handling tests.
6. In `crates/ox-acp/src/acp/convert.rs`, rename the options to `Yes` and `No`
   and add `_meta.subagent_id` to a subagent's permission request. Update the
   tests in `convert.rs` and `acp.rs`.
7. In `crates/ox-fake-server/src/lib.rs`, extend `render` with a completed
   background `shell` call and a nameless completed tool call with content, and
   give the `options` script the `Model`, `ThoughtLevel`, and `Mode` categories
   with an effort option.
8. Rewrite `crates/ox/tests/tui.rs` as described, with `extended-keys on` in the
   tmux configuration and screen captures instead of scrollback.
