# Base58 IDs

## Goal

Every ID Ox makes for its own records (workspace, session, message, and image)
is 64 random bits written in Bitcoin's base58. The page and `oxd` produce the
same format. Sessions already stored with 32-hex-digit or base32 IDs stay
reachable under those IDs.

## Decisions

- **One format.** An Ox ID is 8 random bytes encoded as Bitcoin's
  `EncodeBase58` does: alphabet
  `123456789ABCDEFGHJKLMNPQRSTUVWXYZabcdefghijkmnopqrstuvwxyz`, each leading zero
  byte becomes a leading `1`, and the rest is the big-endian number in base 58
  with no leading zero digit. Its length is 8 to 11 characters, nearly always
  10 or 11. The encoding is a bijection between 8-byte strings and its outputs,
  so a string is an ID exactly when it re-encodes to itself.
- **Go encoder.** `internal/server/id.go` holds `newID() string` and
  `isID(string) bool`. Every caller is in `internal/server`, so no new package.
  `newID` reads 8 bytes with `crypto/rand.Read`, takes them as a `uint64`, and
  encodes that value as 8 big-endian bytes. `isID` rejects a string longer than
  11 characters, parses it as a base-58 number into a `uint64` (a character
  outside the alphabet or an overflow is false; a leading `1` is digit zero),
  and returns whether encoding that value gives back the string. That
  round-trip rejects non-canonical forms such as `12`.
- **TypeScript encoder.** `cmd/ox/web/src/id.ts` exports `newID()` and the
  encoder it uses, `encodeID(bytes: Uint8Array): string`, with the same
  alphabet and algorithm, using `BigInt` for the number. It sits in its own
  module so a Node test can import it; `ox.tsx` drops its `newID` and the two
  callers import from `./id`. The page never validates an ID.
- **Which IDs change.** Workspace, session, message, and image IDs: every ID
  `oxd` and the page mint for Ox's records. They come from `newID` in each
  language, so no `rand.Text()` remains in `internal/server`. Harness-owned IDs
  are unchanged: Claude's session UUID (`newUUID`), Claude's and Ur's
  approval `request_id`s, Ur's conversation token, and the fake harness's IDs.
  The relay's connection key in `cmd/ox/main.go:160` never leaves `ox` and
  stays `rand.Text()`.
- **Boundary and old IDs.** `oxd` checks format only where a client chooses an
  ID: `session_id` on `session/create` and `message_id` on `session/send`, as
  now, with `isID` and the message "session_id must be a base58 ID" /
  "message_id must be a base58 ID". Every other method takes a `session_id` or
  `workspace_id` as a lookup key with no format check, so stored hex and base32
  IDs stay reachable for every action. An old-format `session_id` on
  `session/create` is refused: only a page that loaded before the upgrade would
  send one, and reloading the page fixes it. No store migration.
- **Collisions.** A client-chosen `session_id` that already exists in the same
  workspace makes `session/create` idempotent, so two pages minting the same ID
  would silently share a session. With 64 bits and `oxd`'s case-sensitive map
  and SQLite keys, a pair collides with probability 2^-64. On a
  case-insensitive filesystem, a session ID used as a directory name
  (`<worktrees>/<session_id>`) or a git branch (`ox/<session_id>`, a loose ref
  file under `.git/refs`) folds 58 symbols to 35: 23 letters in both cases,
  plus nine digits and `i`, `o`, `L` in one. Per character two random IDs fold
  equal with probability 104/3364 (about 1/32); with the leading digit's
  narrower range, a pair folds equal with probability about 2^-55. Directories
  and branches share that one space. A 1% chance of any clash needs about
  2^25 (30 million) sessions, so case-folding does not matter for Ox. The
  `session-worktrees` plan treats a clash as an ordinary creation failure and
  assumes only that IDs are fresh and unique.
- **Requirements:** Creating a session, Lost creation reply, and Session URL
  hold unchanged: the draft's ID is minted once per draft as now, a retried
  `session/create` with the same base58 ID still returns `existing: true`, and
  base58 characters need no escaping in the URL's hash or the
  `/images/{session_id}/{image_id}` path. Surviving restarts holds because
  stored IDs are untouched and lookups do not check format.
- **Construction:** "An ID a client chooses is a canonical 64-bit base58
  string" is enforced once, by `isID` at the two boundary checks. "An ID Ox
  mints has this format" holds because `newID` in each language is the only
  source.
- **Trust boundaries:** Session IDs reach file paths and git ref names only in
  the `session-worktrees` change. A client-chosen ID that passes `isID` holds
  only alphanumeric characters, so it cannot form a path separator or `..`.
  Stored old-format IDs are hex or base32, also alphanumeric.

## Test plan

- Encoder vectors, Go: new `internal/server/id_test.go`, because no existing
  test reaches the encoder. Encoding 8 bytes gives:
  `0000000000000000` → `11111111`, `0000000000000001` → `11111112`,
  `00ff000000000000` → `1AfUXwLfh7d`, `0123456789abcdef` → `C3CPq7c8PY`,
  `ffffffffffffffff` → `jpXCZedGfVQ`. `isID` accepts each of those and a fresh
  `newID()`, and rejects `""`, `12`, `0jpXCZedGf` and `ljpXCZedGf`
  (characters outside the alphabet), `jpXCZedGfVR` (overflows 64 bits),
  `111111111` (nine `1`s), and a 32-hex-digit ID.
- Encoder vectors, TypeScript: new `cmd/ox/web/id.test.mjs`, the same five
  vectors through `encodeID`, and `newID()` matches
  `/^[1-9A-HJ-NP-Za-km-z]{8,11}$/`. Added to the `node --test` line in the
  `Makefile`'s `test` target. No existing Node test imports an ID module.
- Boundary, server: in `methods_test.go`'s malformed `session_id` loop, replace
  the cases with a 32-hex-digit ID and `12`, expecting "session_id must be a
  base58 ID". The existing `session/create` and `session/send` tests that pass
  client-chosen IDs switch those IDs to base58 values (from `newID()` or a
  literal vector). A case adds a malformed `message_id` (32 hex digits) to
  `session/send` in the existing test that already sends with a `message_id`,
  expecting "message_id must be a base58 ID".
- Old IDs reachable, server: in an existing test whose store is seeded with a
  session before the server opens (as `TestClaudeRefusesSettingCommandsBeforeStarting`
  seeds `"s"`), seed a session with a 32-hex-digit ID and send it a prompt with
  no `message_id`; the send succeeds and returns a base58 `message_id`.
- The page's IDs reach `oxd`: the existing e2e specs that create a session and
  send prompts run unchanged and exercise base58 `session_id` and `message_id`
  through `isID`.
