# File tree panel

## Goal

The web client gains a right-hand panel, mirroring the left sidebar, that
shows the selected session's workspace directory as a tree. Folders expand and
collapse; each expanded folder is listed by its own request, made when it is
expanded and repeated once a second while the page is visible. A fixed set of
version-control and OS names is hidden at any depth. Each session keeps which
folders it has expanded, so switching sessions and back restores the tree.

## Decisions

- **One method, keyed by workspace.** `workspace/list_folder` takes
  `workspace_id` and `path`, slash-separated and relative to the workspace's
  directory, `""` for the directory itself. It returns
  `{"entries":[{"name":"src","folder":true}, …]}`, `[]` when empty, in
  directory order. Every session works in its workspace's directory, so the
  page asks with the selected session's workspace and never involves the
  session goroutine. The handler copies the workspace's `path` under `s.mu`,
  releases it, and reads the folder outside the lock, so a slow disk holds up
  no other request.
- **Containment by `os.Root`.** The handler opens `os.OpenRoot(path)` and
  lists `root.Open(path or ".")`. `path` is checked at the boundary: it must be
  `""` or satisfy `filepath.IsLocal`, else `-32602` `path must be relative to
  the workspace`. `os.Root` then refuses any symlink that leads outside, so the
  method can list nothing outside the workspace directory.
- **Entries.** Names in `hidden` (`.git`, `.svn`, `.hg`, `.hypercube`,
  `.DS_Store`, `Thumbs.db`) are skipped. A symlink's `folder` is whether
  `root.Stat` of it is a directory; a link leading outside the workspace or
  dangling is a file. `.gitignore` is not consulted.
- **Errors.** Unknown workspace: `-32001` `workspace not found`. A folder that
  cannot be opened or read (missing, not a folder, permission, escape):
  `-32000` with the `os.Root` error text, which names the path relative to the
  workspace.
- **Order is the page's.** The page sorts each listing folders first, then by
  name with `Intl.Collator(undefined, { numeric: true, sensitivity: "base" })`.
- **Expansion lives in the session control.** `createSessionControl` gains
  `expanded`, a store of `Record<string, true>` keyed by folder path, with
  `isExpanded(path)` and `setExpanded(path, open)`. The control already outlives
  the view, is deleted with the session, and carries a draft over to its
  session, so expansion does the same. Collapsing a folder leaves its
  descendants' entries, so re-expanding it restores them.
- **Listings live in the folder that shows them.** `FileTree.tsx` renders the
  root as an always-expanded `Folder` with path `""`. Each `Folder` that is
  expanded owns its latest listing: entries, or an error `oxd` answered. It
  lists itself when it mounts and on each tick of the tree's clock, and only
  folders that appear in their parent's latest listing are rendered, so the
  page asks only for folders it shows. Collapsing unmounts the folder's
  children and drops their listings.
- **One clock per tree.** `FileTree` runs a 1 s interval and tracks
  `document.visibilityState` through `visibilitychange`. A tick lists nothing
  while the page is hidden or `ox.ready()` is false; becoming visible ticks at
  once.
- **One request in flight per folder.** A tick that finds the folder's
  previous request unsettled skips it, so replies apply in the order sent.
- **Only `oxd`'s answers replace a listing.** An `RpcError` replaces the
  entries with its message; any other failure (relay error, lost connection)
  leaves the last listing, since the page already reports the connection.
- **Where the panel shows.** `Layout` renders `<aside class="files"
  aria-label="Files">` after `main` whenever the selection is a session in a
  known workspace or a draft, with that session's or draft's control. The
  `FileTree` is keyed by workspace ID, so switching between sessions of one
  workspace keeps its listings and changes only which folders are expanded.
  Switching workspaces lists afresh.
- **Look.** The panel takes the sidebar's width, background, and border, on
  the left instead of the right. Its header shows the workspace folder's name
  in the style of the sidebar's workspace headings. Each row is indented by
  depth. A folder row is a `<button aria-expanded>` named by the folder, with
  `chevron-right` (rotated when expanded) and `folder` or `folder-open`; a file
  row is plain text with `file`, aligned under the folder icons. An expanded
  empty folder shows a muted `Empty` row; an error shows as a muted row with
  the message in place of the folder's entries, or in place of the tree for the
  root. Names truncate with an ellipsis and carry a `title` of their path.
- **Requirements:** *Working directory* — the tree shows the directory Claude
  works in. *Every request settles* — each list request ends in a reply, an
  `RpcError` shown in the folder that asked, or a rejection from the
  connection, which clears the in-flight mark. *Lost connection* — no request
  is made while disconnected, the tree keeps its last listings, and listing
  resumes on the first tick after reload. *Local access only* — the method is
  served on the same socket and relay as every other. *Unsent text* — expansion
  follows the same lifetime: switching views and reconnecting keep it,
  reloading discards it. A second page, or a workspace removed while a request
  is in flight, needs nothing: every outcome is a valid listing or an error.
- **Settling:** each request waits only on its RPC, which the connection
  settles by reply or by rejecting pending calls on stream error.
- **Construction:** containment is enforced by `os.Root` and the boundary
  check, not by each caller. Expanded state has one source, the session
  control; whether a folder is listed is derived from it and the parent's
  listing, never stored.
- **Ownership:** `oxd` gains no state. The page gains the control's `expanded`
  store (needed to restore the tree across view switches; no races, page-local;
  cleaned up with the control), each `Folder`'s listing and in-flight mark
  (needed to show entries; the in-flight mark keeps an older reply from
  overwriting a newer one; dropped on unmount), and the tree's interval (needed
  for updates without a watcher; cleared on unmount).
- **Trust boundaries:** the method reveals names and folder flags inside a
  registered workspace's directory to anyone who can reach the socket or the
  relay, which already can run Claude there. It reads no file contents and
  writes nothing.

## Check your assumptions

1. **Reloading collapses the tree.**
   - **Plan:** Expanded folders survive switching sessions and reconnecting,
     but a page reload collapses every session's tree, as reloading discards
     unsent text.
   - **Alternative:** Remember expansion in the browser across reloads. Costs
     a little more code and stored state that outlives deleted sessions.
2. **The panel is always open at a fixed width.**
   - **Plan:** The panel shows whenever a session or a new-session draft is
     selected, at the sidebar's width, and cannot be hidden or resized.
   - **Alternative:** A button to hide it and a handle to resize it, remembered
     across reloads. Costs layout code and a remembered setting; the user can
     reclaim space for long transcripts.
3. **Order, empty folders, and unreadable folders.**
   - **Plan:** Folders come first, then names in natural, case-insensitive
     order (`file2` before `file10`). An expanded empty folder shows a muted
     "Empty" line; a folder that cannot be read shows the reason in its place;
     a missing workspace directory shows the reason in place of the tree.
   - **Alternative:** Plain alphabetical order mixing files and folders, and
     empty or unreadable folders showing nothing beneath them. Simpler, but a
     failure looks like an empty folder.

## Test plan

- Server: new `TestListFolder` in `internal/server/methods_test.go`, built
  like `TestSameDirectoryIsOneWorkspace` (no existing test lists a folder). In
  a temp workspace with `src/`, `.git/`, `.DS_Store`, `.gitignore`,
  `ignored.log` (named in `.gitignore`), a symlink to `src`, and a symlink to a
  directory outside: the root lists `src`, both links, `.gitignore`, and
  `ignored.log`, not `.git` or `.DS_Store`; the link to `src` is a folder and
  the outside link is not; `src` lists its entries; an empty folder returns
  `[]`. Refused: `../x` and an absolute path with `-32602`; listing the
  outside link and a file with `-32000`; an unknown workspace with `-32001`.
- E2E: new test in `cmd/ox/web/e2e/workspace.spec.ts` (its setup creates the
  workspace; no existing test covers the panel). With the fake harness, write
  `src/a.txt`, `.git/HEAD`, and `.gitignore` into `services.workspace`, create
  two sessions:
  - the panel lists `src` before `.gitignore` and no `.git`; no
    `workspace/list_folder` request names `src` before it is expanded;
  - expanding `src` shows `a.txt`; a file written into `src` on disk appears
    within a few seconds;
  - the second session shows `src` collapsed; back on the first, `src` is
    expanded with its entries;
  - with `document.visibilityState` overridden to `hidden` and
    `visibilitychange` dispatched, no `workspace/list_folder` request is made
    for two seconds;
  - with a `src` listing held by `hold` past two ticks, no second request for
    `src` is made until it is released;
  - a `src` listing failed by `hold().fail` leaves `a.txt` shown and no error
    row;
  - with `/events` aborted (as in `session.spec.ts`), no request is made and
    the entries stay;
  - a folder with mode `000` shows its `oxd` error beneath it.

## Requirement changes

- **Added:** **File tree.** Beside the transcript, a panel shows the selected
  session's workspace directory as a tree, folders first, whose folders expand
  and collapse. It hides `.git`, `.svn`, `.hg`, `.hypercube`, `.DS_Store`, and
  `Thumbs.db` at any depth, shows files Git ignores, lists nothing outside the
  workspace directory, and shows why a folder cannot be read.
- **Added:** **File tree updates.** While the page is visible, the tree shows
  changes on disk to the folders it shows within about a second.
- **Added:** **File tree expansion.** Each session keeps which folders are
  expanded through switching views and reconnecting; reloading the page
  collapses them.
