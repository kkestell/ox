# Ur's shell calls report what runs and how it ended

## Goal

Resolve [#27](https://github.com/kkestell/ox/issues/27), findings F1, F9, F12,
and F13 of the
[deslop audit](https://github.com/kkestell/ox/blob/main/agents/audits/2026-11-22-deslop-audit.md):

- **F1.** A shell call's arguments are parsed once, strictly, into one value.
  The `tool_use` input, the approval request, and the command that runs all
  come from that value, so the card cannot differ from what runs.
- **F9.** A second stop signal kills Ur's command groups as it kills Claude,
  because both register with one registry of child processes that the daemon
  waits for and kills.
- **F12.** An interrupted Ur call shows as stopped, live and after a reload.
- **F13.** A shell that exited on its own reports its exit status even when
  its timeout passed while a background child held the output pipe, and an
  outcome Ur could not save is still published before the turn's error.

## Decisions

- **One parsed value (F1).** `shellCommand` becomes the parsed arguments with
  JSON tags, `Command string \`json:"command"\`` and
  `TimeoutSeconds int \`json:"timeout_seconds"\``, with the default 120 filled
  in, and a `timeout()` method. `parseShell` refuses anything after the first
  JSON value: after `Decode`, `decoder.Token()` must return `io.EOF`, otherwise
  the error is `arguments: trailing data after the JSON object`. For a call that
  parses, `next` publishes `json.Marshal(command)` as the `tool_use` input, and
  `asking` keeps only `calls`, `command`, and `requestID`; the approval request
  is built from `command` where it is published and in `Snapshot`, by one
  method on `asking`. Re-marshalling also removes the gap Go's case-insensitive
  field matching leaves (`{"Command":…}` runs as `command`); the card shows the
  field that runs. The card now always shows `timeout_seconds`, which is the
  timeout that applies. A call that does not run (unknown tool or invalid
  arguments) keeps today's display: its arguments if they are a JSON object,
  otherwise `{}`. Fold the unknown-tool check and `parseShell` into one
  `parseCall(call toolCall) (shellCommand, error)` so `next` has one error path:
  publish the display input, answer with the error.
- **One registry of child processes (F9).** A new package `internal/children`
  owns the set of processes oxd must wait for and may kill, moved out of
  `internal/claude`:
  - `Start(cmd *exec.Cmd, kill func()) error` starts `cmd` and registers it
    with its `kill`, under the lock, refusing with `daemon is shutting down`
    once `KillAll` has run.
  - `Done(cmd *exec.Cmd)` removes it and broadcasts.
  - `WaitAll()` returns once the set is empty; `KillAll()` marks the set killed
    and calls every `kill`.

  Claude registers with `kill` = `cmd.Process.Kill` and calls `Done` after
  `cmd.Wait`. Ur registers with `kill` = `killGroup(pid)` and calls `Done`
  after `cmd.Wait` and its own `killGroup`. The daemon calls `children.WaitAll`
  after `Server.Close`, and `children.KillAll` on the second signal. A harness
  that starts a process through `children` cannot be missed by either path.
- **Ur registers on the session goroutine.** `runShell` splits into
  `startShell(ctx, workspace, c) (*shell, error)`, which builds the command
  and calls `children.Start`, and `(*shell).wait() outcome`, which waits, kills
  the group, calls `Done`, and reads the status. `execute` calls `startShell`
  on the session goroutine and `wait` on its own goroutine, so a command is
  registered before `Stop` returns and `WaitAll` cannot miss it, as the
  synchronous `commands.Add` guaranteed. A start error is answered with
  `Could not start bash: <err>` as today. `ur.WaitAll` and `commands` go.
- **Interrupted call (F12).** `Interrupt` publishes no `tool_result`, as `Stop`
  and a restart already do: it cancels a pending approval, then finishes with
  `Interrupted`. The conversation file has no tool entry for the call, so
  `conversation` answers it with `stopped` as before. The page marks every
  tool without a result stopped when a `result` arrives, as it does on
  `exited` and `parked`. A stopped call expanded shows its input and no result
  text; the marker says stopped.
- **Exit status first (F13).** `wait` reports `Exit code: N` when
  `status.Exited()`, then `Timed out after N seconds` when the deadline passed,
  then the signal. Ur kills the whole group on timeout, so a timed-out bash is
  always signalled, and a bash that exited on its own keeps its status.
- **Unsaved outcome (F13).** `answer` publishes the `tool_result` first, then
  saves; a failed save ends the turn with `Ur could not save the command's
  result: …`. The model, reading the file after a restart, gets `stopped` for
  that call, because Ur's history is exactly the file.
- **Requirements:** **Allow and Deny** holds by construction: the card and the
  command are one value. **Tool calls** gains the stopped state for Ur's
  interrupted calls; a reload replays the same updates through `apply`, so the
  page shows the same state live, after a reconnect, and on a second page.
  **Ur's shell commands** reports the status of a command that exited on its
  own, and a saved or unsaved outcome reaches the transcript. **Stopping oxd**
  holds for Ur commands on the second signal. **Stop** is unchanged: the turn
  ends with `Interrupted` and pending prompts are dropped as before.
- **Settling:** `children.WaitAll` waits for each registered process to be
  reaped and `Done` called. Claude's processes end as today; an Ur command ends
  at its exit, its timeout (at most 600 s), or the turn's cancellation, which
  `Server.Close` causes by stopping each session. A second signal bounds both.
- **Construction:** the card, the `tool_use` input, and the command are the
  one `shellCommand`; `asking` holds no second copy of the request. Every child
  process oxd waits for or kills is in the one `children` set.
- **Ownership:** the `children` set moves from `internal/claude` unchanged in
  kind: a mutex-guarded map from process to its kill function, a `killed` flag,
  and a condition variable. It is needed so a second stop signal ends every
  Claude process and Ur command (**Stopping oxd**). Its race is a start during
  `KillAll`, which the lock and `killed` close: a start after `KillAll` is
  refused. Cleanup is `Done` after each reap. The commit body repeats this.
- **Claude Code:** the page's new rule assumes every top-level `tool_use` gets
  its `tool_result` before the turn's `result`. The
  [Interrupt](../../docs/harnesses/claude-code.md#interrupt) sequence sends the
  running tool's `tool_result` before `result`, and the late lines in
  [When a turn ends](../../docs/harnesses/claude-code.md#when-a-turn-ends)
  belong to subagents, which the transcript leaves out. Claude's interrupted
  tools keep their error result and still show failed.

## Test plan

- Trailing text after a valid command object is refused: `TestShellArguments`
  gets `{"command":"touch wrong"} trailing` and `{"command":"touch wrong"}{}`.
  `TestShellInvalidCall` gets a call with `{"command":"touch wrong"} extra`,
  answered with an `arguments: ` error, its `tool_use` input `{}`, no approval,
  and no `wrong` file (Ur harness). Its default-timeout assertion reads
  `TimeoutSeconds == 120`.
- The card shows the parsed value: `TestShellApproved` expects the `tool_use`
  input and the approval request's `input` to be
  `{"command":"echo hi","timeout_seconds":120}`, and the snapshot's approval to
  carry the same request (Ur harness).
- An interrupted call publishes no `tool_result`: both subtests of
  `TestShellInterrupt` expect `approval_cancelled`/`result`/`state idle` without
  `tool_result`, and keep their checks that the next request answers the call
  with `stopped` (Ur harness).
- A shell that exits on its own after its deadline passed reports its status:
  new `TestShellExitAfterDeadline` in `shell_test.go` runs
  `sleep 60 & echo $! > child; sleep 0.5` with `timeout_seconds` 1 and expects
  `Exit code: 0` without `isError`, and the child gone. No existing test runs a
  command that exits before its timeout with a child holding the pipe past it.
- An unsaved command outcome is still published: new subtest `command result`
  in `TestSaveFailure`, in auto mode, runs a command that waits for a file
  `go` in the workspace; the test waits for `tool_use`, makes the conversation
  file read-only, writes `go`, and expects a `tool_result` with `Exit code: 0`
  before an error `result` starting `Ur could not save the command's result: `.
- A second stop kills Ur's command groups: new `TestKillAllEndsCommands` in
  `internal/ur/shell_test.go` re-runs the test binary on itself
  (`-test.run=^TestKillAllEndsCommands$` with an environment variable), because
  `KillAll` refuses later starts for the whole process. The inner run starts
  `sleep 60 & echo $! > child; sleep 60` with `startShell`, waits for `child`,
  calls `children.KillAll`, expects `wait` to return and the child to be gone,
  and expects a second `startShell` to fail. The outer run checks the inner
  run passed. The daemon's call to `children.KillAll` stays covered by
  `TestDaemonOwnsSocketAndDatabaseUntilShutdown`, which kills Claude through
  the same set.
- The page shows a tool its turn ended without a result as stopped: new e2e in
  `session.spec.ts`, beside "a tool whose process ended with oxd shows
  stopped". An init script wraps `EventSource`, as `cutReply` in `ui.ts` does,
  and drops each `session/update` whose `params.type` is `tool_result`. The
  test asks the fake for a `Bash` approval, presses Stop, and expects the
  tool's marker to read `stopped`. Before the change it reads `running`.

- `TestLiveUr` waits for the command to run and checks it is gone: audit F5
  assigns the test to this change. Its auto-mode section asks for `echo $$ >
  running; sleep 30`, waits for the file `running` rather than for `tool_use`,
  which Ur publishes before the command starts, interrupts, expects no
  `tool_result`, and expects the recorded shell PID to be gone.

## Implementation plan

1. Add `internal/children/children.go` with `Start`, `Done`, `WaitAll`, and
   `KillAll` as described, moving the set, its condition variable, and the
   `daemon is shutting down` refusal from `internal/claude/claude.go`. Replace
   Claude's `spawn`, `wait`, `WaitAll`, and `KillAll` with calls to it, keeping
   the stderr and stdout handling around them unchanged.
2. In `cmd/oxd/main.go`, call `children.WaitAll` instead of `claude.WaitAll`
   and `ur.WaitAll`, and `children.KillAll` instead of `claude.KillAll`. Update
   the comment at the top of `run` to say the socket is held until every child
   process has exited.
3. In `internal/ur/shell.go`: give `shellCommand` its JSON fields and
   `timeout()`; make `parseShell` refuse trailing data; split `runShell` into
   `startShell` and `(*shell).wait`, registering through `children`, checking
   `status.Exited()` before the deadline; remove `commands` and `WaitAll`.
4. In `internal/ur/ur.go`: add `parseCall`; rewrite `next` to publish the
   display input and answer on error, or publish `json.Marshal(command)` and
   run or ask; drop `request` from `asking` and build it from `command` in one
   method used by `next` and `Snapshot`; make `execute` call `startShell` on the
   session goroutine; make `answer` publish before saving; make `Interrupt`
   publish no `tool_result` and update its comment.
5. In `cmd/ox/web/src/ox.tsx`, call `stopTools` on `result`, and update the
   `Entry` comment: a tool is stopped when its turn ended or its process exited
   before its result.
6. Update the tests listed in the test plan.
7. Update the documents below.
