# File viewer

## Goal

Clicking a file in the workspace file tree opens it in a pane between the
chat and the tree. The chat and the pane split the space 50/50. Above the pane
is a tab bar as tall as the chat's `header.context`, holding one tab with the
file's icon, name, and a close button, styled after Hypercube's editor tabs.
The pane shows the file's text in a monospaced font, unwrapped, and follows
changes on disk within about a second. Each session and each new-session draft
keeps its own open file, as it keeps its expanded folders.

## Decisions

- **`workspace/read_file`.** Takes `workspace_id` and `path`, which must
  satisfy `filepath.IsLocal` (so `""` is refused with the same
  `path must be relative to the workspace`, `-32602`). Unknown workspace:
  `-32001` `workspace not found`. Returns `{"text": "…"}`.
- **What oxd refuses to show.** `readFile(dir, path)` opens `os.OpenRoot(dir)`,
  calls `root.Stat(path)` and refuses anything but a regular file with
  `not a regular file` (checked before opening, so a FIFO cannot block the
  read), opens it, and reads at most `1<<20 + 1` bytes. More than `1<<20`:
  `file is larger than 1 MiB`. A NUL byte in the first 8000 bytes:
  `file is binary`. `!utf8.Valid`: `file is not UTF-8 text`. These and every
  `os.Root` error (missing, permission, a symlink leading outside) return
  `-32000` with the message. The page therefore has one shape for every
  outcome: text, or a message from `oxd`.
- **One clock per page.** The 1 s clock moves from `FileTree` into the
  provider as `ox.clock`, a signal that advances once a second while the page
  is visible and `ready()`. The tree and the viewer tick together.
- **One polling rule.** `src/poll.ts` exports `createPoll(request)`, which
  runs `request` when created and on each tick of `ox.clock`, skips a tick
  while its previous request is unsettled, and returns an accessor of
  `Polled<T> = { kind: "value"; value: T } | { kind: "error"; message: string }`,
  `undefined` until the first answer. An `RpcError` sets `error`; any other
  failure keeps the last result. `Folder` uses it for listings, replacing its
  own in-flight mark and `Listing` type; `FileView` uses it for reads.
- **The open file lives in the session control.** `createSessionControl` gains
  `file` (`createSignal<string>()`, the open file's path) and `setFile`. The
  tab, the pane, and the tree's highlight all derive from it. Clicking a file
  row calls `setFile(path)`; setting the same path changes nothing, so the
  open file's view is untouched. Close calls `setFile(undefined)`. The control
  outlives views, is per session and per draft, carries a draft's state to
  its session, and is dropped on reload, exactly the lifetime required.
- **Content lives in the view of one file.** `Layout` renders, inside the
  existing workspace-keyed block and before `FileTree`,
  `<Show when={control.file()} keyed>` a `FileView` for that path. A view
  exists for one workspace and one path, so another file's text can never show
  under its tab, and a late reply for a replaced file lands in a disposed view.
  Two sessions of one workspace with the same file open share the view.
- **The pane's text.** `FileView` derives `text` with `createMemo` from the
  polled result, so an unchanged file writes nothing to the DOM and the scroll
  position holds. While the first read is in flight the pane is empty. An
  error shows as one muted line in place of the text; the tab stays.
- **File rows become buttons.** A file row becomes
  `<li><button type="button" class="row" title={path} aria-current=…>` with the
  `file` icon, matching folder rows, so it is clickable and focusable. The
  open file's row has `aria-current="true"` and the sidebar's selected look
  (`background: var(--secondary); color: var(--secondary-foreground)`). The
  file row keeps its icon aligned under folder icons.
- **Layout and look.** `<section class="viewer" aria-label="File">` sits between
  `main` and `aside.files`; both `main` and the viewer are `flex: 1;
  min-width: 0`, and the viewer has `--pane` background and a left border.
  `:root` gains `--context-title: 2.75rem` and `--context-path: 2.25rem`, used
  by `.context h1`, `.context .path`, `aside.files > p`, and the viewer's
  `header`, whose height is
  `calc(var(--context-title) + var(--context-path) + 2px)` with a bottom
  border, so the two headers match. The header is a flex row, items centered,
  padding `0 0.5rem`, holding `<div role="tablist" aria-label="Open files">`:
  `display: inline-flex`, height `1.75rem`, padding `3px`,
  `border-radius: var(--radius)`, `background: var(--muted)`. Inside, a
  `.tab` (flex, min-width `6rem`, max-width `16rem`) holds a
  `<button role="tab" aria-selected="true" title={path}>` (padding
  `0.25rem 0.5rem`, gap `0.375rem`, `border-radius: var(--radius-md)`,
  `0.875rem`, weight 500, `color: var(--foreground)`, no border, background,
  or shadow; the name truncates) with the `file` icon and the file's name, and
  a `button.icon.x` (`1.5rem` square, ghost, `hover: var(--accent)`, a
  `0.75rem` Lucide `x` from lucide-static) labeled and titled
  `Close <name>`. The content is `<pre role="tabpanel">`: flex 1, `overflow:
  auto`, `white-space: pre`, `font-family: var(--font-mono)`, `0.75rem`,
  padding `0.5rem 0.75rem`.
- **Requirements:** *File tree* — rows look as before, and a file row is now a
  button. *File tree updates* — unchanged; the tree ticks on the page's clock.
  *Every request settles* — each read ends in text, an `RpcError` shown in the
  pane, or a connection rejection that clears the in-flight mark. *Lost
  connection* — no read is made while disconnected, the pane keeps its text,
  and reading resumes on the first tick after reload. *Local access only* —
  the method is served on the same socket and relay. *Working directory* —
  files are read from the directory Claude works in. A second page keeps its
  own open file; a file changed, deleted, or a workspace removed during a read
  needs nothing, as every outcome is text or an error.
- **Settling:** a read waits on its RPC, which the connection settles by reply
  or by rejecting pending calls. On `oxd`, reading is bounded at 1 MiB + 1
  byte and only regular files are opened.
- **Construction:** containment is enforced by `os.Root` and the boundary
  check. The open file has one source, the control's `file`; tab, pane, and
  highlight derive from it. Content cannot outlive its path because it lives
  in a view keyed by path. The polling rule exists once, in `createPoll`.
- **Ownership:** `oxd` gains no state. The page gains the control's `file`
  (needed to keep each session's and draft's open file across view switches;
  page-local, no races; dropped with the control) and each `FileView`'s polled
  result and in-flight mark (needed to show the text; the mark keeps an older
  reply from replacing a newer one; dropped on unmount). The clock moves to
  the provider, one interval per page, cleared when the provider is disposed.
- **Trust boundaries:** the method returns the contents of regular files up to
  1 MiB inside a registered workspace's directory to anyone who can reach the
  socket or relay, who can already run Claude there. `os.Root` refuses paths
  and symlinks that lead outside; devices and FIFOs are refused before
  opening. It writes nothing.

## Check your assumptions

1. **A draft's open file carries into its session.** Kept.
   - **Plan:** A file opened while writing a new session's first prompt stays
     open in the session that prompt creates, as the draft's expanded folders
     do.
   - **Alternative:** The new session starts with no file open. Costs the user
     reopening the file they were referring to.

## Test plan

- Server: `TestListFolder` in `internal/server/methods_test.go` becomes
  `TestWorkspaceFiles`, since its workspace (files, a symlink to a file,
  symlinks leading outside) already reaches every read case. Add `src/main.go`
  content, a file symlink `leak` to a file in `outside`, `bin.dat` with a NUL,
  `big.txt` of `1<<20 + 1` bytes, `latin1.txt` with `0xff`, and a FIFO
  `pipe` (`syscall.Mkfifo`). Assert: `src/main.go` and `notes` return their
  text; `bin.dat`, `big.txt`, `latin1.txt`, `src`, `pipe` (returning promptly),
  `leak`, and a missing file return `-32000` with the reason; `""`, `../x`, and
  an absolute path return `-32602`; an unknown workspace `-32001`.
- E2E: new test in `cmd/ox/web/e2e/workspace.spec.ts`, "the file viewer shows
  each session's open file". The tree test covers polling's in-flight, hidden,
  relay-failure, and lost-connection cases, which now run through
  `createPoll`; the viewer's cases need their own files and sessions. With the
  fake harness, write `src/a.txt` (a line longer than the pane) and `bin.dat`,
  create two sessions:
  - in the first, expanding `src` and clicking `a.txt` shows a tab named
    `a.txt` titled `src/a.txt`, the text, and `aria-current="true"` on its
    row; the tab bar's height equals `header.context`'s, `main` and the viewer
    are equally wide, and the text scrolls horizontally;
  - writing new text into `src/a.txt` shows it within 3 s;
  - clicking `a.txt` again leaves the same `<pre>` element (marked with a
    data attribute through `evaluate`);
  - deleting `src/a.txt` keeps the tab and shows `no such file or directory`;
    writing it back shows its text;
  - clicking `bin.dat` replaces the tab and shows `file is binary`;
  - the second session shows no viewer; back on the first, `bin.dat` is open;
  - Close removes the viewer and the row's `aria-current`;
  - in the workspace's draft, opening `a.txt` shows the viewer; switching to
    a session and back keeps it; submitting the draft leaves `a.txt` open in
    the created session;
  - reloading the page shows no viewer.

## Requirement changes

- **Added:** **File viewer.** Clicking a file in the file tree opens it in a
  pane between the transcript and the tree, under a tab with its name and a
  close button, and highlights its row; clicking another file replaces it. The
  pane shows the file's text in a monospaced font without wrapping, or one
  line saying why when the file is binary, larger than 1 MiB, not UTF-8 text,
  or cannot be read, and reads nothing outside the workspace directory.
- **Added:** **File viewer updates.** While the page is visible, the open file
  shows changes on disk within about a second; a file deleted or renamed keeps
  its tab and shows why it cannot be read until it returns.
- **Added:** **Open file.** Each session, and each workspace's new-session
  draft, keeps its open file through switching views and reconnecting, and a
  draft's open file stays open in the session it creates; reloading the page
  closes it.
