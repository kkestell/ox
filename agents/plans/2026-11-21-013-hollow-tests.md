# Tests that fail when their behavior breaks

## Goal

Six tests pass when the behavior they name breaks
([Deslop F8](../audits/2026-11-20-002-deslop.md#f8-tests-that-pass-when-the-behavior-they-name-breaks),
todo entry "Tests that pass when their behavior breaks"). Each one is corrected
to assert the observable that carries its behavior: the settings and flags of
the next start, the bytes written to Claude, the page's Send state after a
reconnect, the denied tool's result, and, in `TestLive`, orderings fixed by
gates instead of clocks. `TestLive` becomes named `t.Run` sections that each
build their own sessions, so `-run TestLive/<name>` selects one and a refusal
from Haiku ends only its section. When done, each test fails under the mutation
or probe named for it below. No product behavior changes.

## Decisions

- **Ordering-dependent `TestLive` sections move to stand-in tests.** Real
  Claude's startup and acknowledgement timing cannot be gated, and the
  behaviors in question are `oxd`'s, not Claude's. The "holds up only its own
  requests" section is deleted, since `TestStartAndStopHoldUpNoOtherSession`
  already proves it with a gate. The destroy section becomes a new server test
  with a stand-in whose initialize and configure acknowledgements wait on
  gates.
- **Each `TestLive` section is self-contained.** A section creates every
  session it uses, so it runs alone under `-run`. Sections run in source order
  without `t.Parallel`; the two that restart the daemon do so inside their own
  section and leave the restarted daemon for the sections after them.
- **Each section has its own client bound to its `t`.** `client` calls
  `c.t.Fatal`, and a subtest must not fail its parent's `t`. The helpers become
  methods of a small `live` type holding the section's `*client`, the
  workspace ID, and the section's `t`, so `turn`, `refuse`, and the rest report
  to the section.
- **Negative parking checks wait on a control that parks.** Where a section
  asserts that a session did not park, it first runs a completed turn on a
  control session with nothing scheduled, after the sessions under test are
  idle, and waits for the control's `parked` update. Since the control became
  idle last, the sessions under test have been idle for at least the park
  period. This replaces `time.Sleep(parkAfter + 5s)` and
  `time.Sleep(4s)`.
- **The restored-schedule section proves the job was restored.** After the
  interrupted first turn on resume, the section runs a completed turn on the
  scheduled session. Its Stop report lists the job `--resume` restored, so the
  session still does not park, while a resumed control with nothing scheduled
  parks after its completed turn. Without the restored job, that turn's empty
  Stop report would let the session park.
- **The running session in `TestConfigurationTakenButNotStored` is checked
  through `session/get`.** Its next start needs it to park, which the fake
  cannot do at a point the test controls. `session/get` and the next start both
  read `sess.settings`. The parked session is checked at its next start, through
  a test harness that wraps `fake.Start` and records each `Options.Settings`.
- **Typed denial asserts the transcript.** The Bash call's result in the
  transcript must contain the typed text. Whether Claude's `tool_result` for a
  deny carries `message` is not recorded in
  [Claude Code §5](../../docs/harnesses/claude-code.md#5-permissions-and-questions),
  which says only that a deny becomes a tool error (`"User declined"`). The
  `make live` run settles it, and its result is recorded in §5. If Claude's
  result does not carry the text, the assertion is instead that the page's
  `session/approve` post carries `response.message: "Do not create files."`
  (`page.waitForRequest` on `/rpc`), and §5 records that the message does not
  reach the transcript.
- **Requirements:** each test guards an existing requirement without changing
  it: **Settings shown are settings used**, **Claude's own mode changes**,
  **Message delivery**, **Ox's instructions**, **Lost connection**, **Allow and
  Deny**, **Parking**, and **Deleting a session**.
- **Claude Code:** the restored-schedule section relies on §8: `--resume`
  restores unexpired main-thread recurring jobs, a resumed process reports them
  only when its first turn ends, and an interrupted turn sends no Stop callback.
  The typed denial relies on the live check above.

## Test plan

Each corrected test must fail under its named mutation or probe, and pass
without it.

- **Server, `TestConfigurationTakenButNotStored`.** Mutation: in `adopt`, on
  the save-error branch, restore the previous `sess.settings` (keep the
  broadcast).
- **Server, `TestClaudeModeChangeIsAdopted`.** Mutation: in `session.start`,
  pass `PermissionMode: "plan"` in `agent.Options.Settings` instead of
  `sess.settings.PermissionMode`.
- **Claude harness, `TestPromptSentWhileClaudeWorks` and
  `TestInputWaitsForStartup`.** Mutation: in `prompt.go` `write`, pass
  `input.Text` instead of `input.Content` to `a.input.Prompt`.
- **E2e, "a reconnect keeps typed text and sends nothing again".** Injected
  fault: in `ox.tsx` `reload()`, `return` before
  `await Promise.all([...listed].map(load))`.
- **Live e2e, `approval.spec.ts` typed denial.** Mutation: in
  `ApprovalRequest.tsx:46`, send `"Denied by user"` for the Other choice too.
- **Server, new `TestDestroyWhileStartingOrConfiguring`.** Mutation: in
  `session.destroy`, move the `sess.stop()` block after the `session/destroyed`
  broadcast. Both halves must fail: the starting half on the `prompt_cancelled`
  or `parked` update that follows, the configuring half on the
  `session/configured` and `parked` updates that follow. No existing test
  reaches a destroy while Claude starts or configures with gated timing.
- **Live, `TestLive/parking`.** Mutation: in `park.go`, ignore the Stop
  report's crons (`a.mayHaveSchedules = false`). The section fails on the
  completed-cron session parking before the control.
- **Live, `TestLive/restored schedules`.** Probe: remove the `CronCreate` turn
  from the section's setup, so the session resumes with no job. The old section
  passes under this probe; the new one fails at the completed turn after
  resume, when the session parks.
- **Live, `TestLive` selection.** `go test -run 'TestLive/failed_start' ./internal/server`
  with `OX_LIVE=1` runs that section alone.

   and `TestInputWaitsForStartup`, decode `message.content` from the written
   line alongside `uuid` and `priority`, and require `"wrapped steer"`.
2. **`internal/server/methods_test.go`, `TestConfigurationTakenButNotStored`.**
   Replace the harness map's `fake.Start` with a function that sends
   `options.Settings` on a buffered `started` channel and returns
   `fake.Start(options)`. Drain the first start's settings. After the two
   configurations, keep the `session/configured` check, then:
   - `session/get` for the running session reports `effort` `high`;
   - `session/send` to the parked session, and the next value on `started` is
     `agent.Settings{Model: "m", Effort: "high", PermissionMode: "plan"}`.

   Update the comment above the test to say the settings taken are the ones the
   next process starts with.
3. **`internal/server/methods_test.go`, `TestClaudeModeChangeIsAdopted`.** Head
   the script with `logStarts(args)`. After the status line, the stand-in
   prints a `result` with
   `"session_id":"11111111-1111-4111-8111-111111111111"`, as in
   `TestResumeTokenKeptWhenNotStored`, and exits. Keep the three existing
   checks. Then wait for `parked`, `forget`, send again, wait for `result`, and
   require `starts` to have two lines, the second containing
   `--resume=11111111-1111-4111-8111-111111111111` and
   `--permission-mode=manual`. Update the comment above the test to name later
   processes.
4. **`internal/server/methods_test.go`, new
   `TestDestroyWhileStartingOrConfiguring`**, after
   `TestStartAndStopHoldUpNoOtherSession`. Config: harness `claude` with model
   `m` (efforts `low`, `high`) and mode `manual`. Two stored sessions, `d` and
   `b`. Stand-in script: read the initialize line; wait until the `started` gate
   file exists; acknowledge initialize; `takePrompt`; print
   `session_state_changed` `idle`; read one line (the configuration); touch the
   `configuring` file; `exec cat >/dev/null`.

     on the gate), then `session/destroy` `d`, which succeeds.
   - Configuring: create the `started` gate, `session/send` to `b`, wait for
     `idle`, `c.send` `session/configure` `b` `effort: high`, poll until the
     `configuring` file exists, then `session/destroy` `b`, which succeeds, and
     the configure reply arrives.
   - After each destroy's reply, a `workspace/list` round trip, then the
     session's last received notification is `session/destroyed`.
5. **`internal/server/live_test.go`, `TestLive` setup.** Keep the outer setup:
   configuration with the misspelled mode, store with the lost session,
