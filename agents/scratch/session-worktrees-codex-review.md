**Revise the worktree plan before implementation.** The directory prerequisite is viable with two corrections. The worktree plan has several paths that can publish a session whose checkout has been removed, delete a checkout another session is still using, or leave resources behind after a failed creation.

I reviewed `9e6cb61`, which matches the checkout’s `origin/main` ref. The findings below are confirmed from the current Ox source, the written plans, or Git’s source. I didn’t run tests that write files or change the checkout. GitHub’s issue list was unreachable, so I couldn’t check for duplicate open bugs.

## Confirmed findings

### High

1. **Child rollback can remove a published child’s checkout.** `addChild` publishes the child, then returns the result of `acceptMessage`. If the first `Send` fails, the child is already listed and its goroutine starts anyway. The planned discard path would force-remove its checkout and try to delete its branch. There is a second ordering problem before publication: on shutdown, `addChild` calls `Stop` and returns while the process can still be exiting. And if deleting the unpublished row fails, the current code logs the error and leaves a row that a restart will load. **Fix:** make publication the explicit transfer of ownership. Before publication, only discard after the harness has drained and the row is known to be absent. Consider moving the child’s insert to publication after successful launch, if the fresh-start callback contract permits it. After publication, report a first-message failure with the child ID and preserve its checkout. Keep cleanup off the parent goroutine. [Worktree plan](/Users/kyle/.local/share/worktrees/ox/session-worktrees/agents/plans/2026-11-22-session-worktrees.md:40) · [Child publication and first Send](/Users/kyle/.local/share/worktrees/ox/session-worktrees/internal/server/mcp.go:390) · [Existing failed-row-cleanup test](/Users/kyle/.local/share/worktrees/ox/session-worktrees/internal/server/mcp_test.go:542)

2. **The proposed Stop channel misses processes that can still write.** Parking and archiving call `sess.stop`, which immediately drops the agent. Delete a just-parked session and there is no agent left to supply the channel. For Claude, the proposed close at `cmd.Wait` covers the CLI process only. Ox currently signals that PID, and an existing test explicitly shows that a descendant can outlive it. For Ur, `Interrupt` cancels and drops the turn before its shell waiter finishes, so `Stop` looking at the current turn misses the interrupted command. **Fix:** retain the completion barrier across parking, archive, and agent replacement, or drain before relinquishing the runtime. Have each harness account for the writers it actually owns. Claude needs a verified policy for tool descendants, and Ur needs to retain shell completion independently of the turn. Close the barrier from process cleanup, independently of event delivery to the session that is waiting. Treat `killAfter` as the signal escalation delay. 3. **Directory location neither establishes ownership nor protects all users of a checkout.** Change `-worktrees` or `XDG_DATA_HOME` across a restart and a managed session becomes Local for listing and deletion, leaving its checkout behind. In the other direction, the RPC accepts a caller-selected ID and an existing workspace directory. A Local session created with the matching ID inside a manually created linked checkout can be misidentified as its owner. The leaf check also misses other users of the directory. An unrelated session can create a child with `dir` set to the checkout, or the user can add it as another workspace and start a Local session there. The owner can then delete a checkout with a live writer. **Fix:** persist the managed checkout identity as part of the session location. A Local directory and a managed root plus relative directory are two variants. At admission, reject unrelated sessions using a managed checkout, including through aliases, unless cross-session sharing is an intended feature with its own lifecycle. Ordinary descendants can keep sharing under the existing leaf rule. 4. **An SQLite duplicate check arrives too late to protect the worktree path.** Two requests can pass step 1 with the same explicit ID in different repositories. They get the same filesystem destination and independent Git refs. Git checks the candidate path before writing its `.git` link, so both can pass that check before either writes. Step 3 runs after the checkouts have already competed for the path. Even in one repository, a retry during checkout can get “branch already exists” instead of the existing-session outcome it would get after publication. **Fix:** give one in-flight creation ownership of each ID and destination before releasing `Server.mu`. Resolve same-workspace retries against that attempt and reject cross-workspace reuse. Keep the Local path in its existing single lock section. The proposed step-3 workspace identity check is sound and can stay. 5. **Failed `worktree add` can leave both the checkout and branch.** Git runs `post-checkout` after it has finished creating the checkout. If the hook exits nonzero, Git reports failure and deliberately leaves the worktree registered. The plan only attempts `branch -D` on this path, and Git refuses to delete the branch while it is checked out. A successful hook can also create untracked files despite the proposed “only committed files” requirement. **Fix:** decide explicitly whether Ox runs checkout hooks. If it does, treat add failure as a possible partial success and roll back only the branch and registration proven to belong to this attempt. Join cleanup errors and preserve a pre-existing destination. ### Medium

6. **The request goroutine can lose its cleanup context or be cut off by graceful shutdown.** A child checkout can finish after its parent’s worktree has been deleted. `post` then refuses the child, and rollback from the original `base` fails because that directory is gone. Separately, `Server.Close` waits for published sessions, and `oxd` waits for registered harness processes. Neither waits for request-side Git and its cleanup. Shutdown during checkout can therefore exit before step 3 or discard. **Fix:** resolve a repository context that survives deletion of the source checkout before starting Git. Keep admitted create operations owned through cleanup during graceful shutdown, with no Git under `Server.mu`. Define the behavior of a blocked hook and distinguish graceful shutdown from forced exit. [Child creation and discard](/Users/kyle/.local/share/worktrees/ox/session-worktrees/agents/plans/2026-11-22-session-worktrees.md:29) · [Server shutdown](/Users/kyle/.local/share/worktrees/ox/session-worktrees/internal/server/server.go:143) · [Daemon shutdown](/Users/kyle/.local/share/worktrees/ox/session-worktrees/cmd/oxd/main.go:87)

7. **Delete’s result can misrepresent what remains on disk.** Returning success immediately for a missing folder leaves the Git registration until a later prune. Conversely, Git can return an error after it starts removing files and can still remove its registration. A successful removal followed by `DeleteSession` failing also leaves a listed row whose directory is gone. Ur currently accepts a missing directory at start, treats missing `AGENTS.md` as normal, and only fails when it tries to launch a shell. **Fix:** do targeted cleanup from a surviving repository context when the folder is missing, including for children created from an explicit `dir` in another repo. Distinguish a safety refusal from a failed removal or row deletion. Preserve history, fail start clearly when the stored directory is gone, and make a repeated Delete finish the remaining work. Crash recovery or automatic checkout recreation adds no value to this fix. 8. **The placement and prefix rules allow a session to start outside its checkout or in a missing directory.** The planned dev override puts worktrees in `.state`, which is inside the dev checkout. A production override can also point inside the source repository. Separately, a workspace subfolder containing only untracked files does not appear in the fresh checkout. If the source has a local directory where `HEAD` has a symlink, joining `<root>/<prefix>` can even resolve outside the new checkout. **Fix:** resolve the configured root to an absolute path, validate physical containment against the source checkout, and use an isolated dev path outside the checkout. Before publication, verify that the mapped directory exists and resolves inside the new root. Route a failed validation through creation rollback. 9. **The deletion policy is stricter for detached HEAD and weaker for ignored files.** A clean worktree detached at a commit already on `ox/<id>` is safe under the note’s `for-each-ref --contains HEAD` rule, but the plan explicitly refuses it. That is a defensible product choice. 10. **The directory prerequisite keys a session-specific request by directory.** `FileTree` and `FileView` currently capture the RPC selector when they mount. ## Research coverage and simplification

Of the five constraints, **retaining the session-ID branch after publication** is sound. **Stopping writers and checking before an unforced Delete** needs findings 2, 3, and 9 resolved. **Running cleanup from a surviving repository context** was dropped. **Flat placement outside checkouts** is intended but unenforced. **Completing checkout before publication under the membership owner** works for top-level workspace membership, but leaves the ID, child handoff, and shutdown gaps above. There is one more product difference to record: the note says an opted-in child starts from the workspace’s `HEAD`, while the plan uses the parent’s directory or the explicit `dir`. Those commits can differ. [Research proposal and constraints](/Users/kyle/.local/share/worktrees/ox/session-worktrees/agents/scratch/session-worktrees-history.md:399)

Across **A–J**, A and B remain open in rollback and admission. C’s branch, tip, and merge caches stay out. D and E remain open in quiescence, ignored files, and missing or partially removed directories. F and G need placement enforcement and destination ownership. H drops copying and setup but still runs checkout hooks and consumes Git path output. I and J stay out of scope. The proportionate design is one creation ownership transfer, one durable session location, and one process completion barrier. The existing membership lock and parent goroutine already supply the serialization needed at publication. ## Speculative risks

- An independent terminal can write or change `HEAD` between Ox’s checks and Git’s removal. The confirmed cases above involve writers Ox can account for. Keep Git’s unforced removal and apply the untracked-file override to its internal status check too. A stronger guarantee against unrelated external writers needs evidence before introducing coordination.
- Forced exit or power loss can interrupt the Git-and-SQLite sequence. State the limit explicitly. The graceful-shutdown defect warrants a fix, while crash reconciliation would be a separate product decision.
