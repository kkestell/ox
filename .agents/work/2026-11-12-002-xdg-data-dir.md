## Brief

Data directory rule (design, "Data directory and worktree location", first
paragraph):

> `ox_protocol::data_dir()` is the one lookup. It is `$XDG_DATA_HOME/ox` when
> `XDG_DATA_HOME` is set to an absolute path, else `<home>/.local/share/ox`, else
> `<temp dir>/ox` when there is no home, on every platform.
> `default_socket_path()` is `$OX_SOCKET`, else `data_dir()/oxd.sock`. Nothing
> else in Ox computes a data path. The bridge applies the same rule to
> `claude-code-acp` (`CLAUDE_ACP_STORE_DIR` still overrides). No migration: the
> old `~/Library/Application Support/ox` is neither read nor removed.

Brief (design, "Brief: `2026-11-12-002-xdg-data-dir`"):

> - `crates/ox-protocol/src/client.rs`: add `pub fn data_dir() -> PathBuf`, the
>   rule in **Data directory and worktree location**, built on a private pure
>   `data_dir_from(xdg: Option<OsString>, home: Option<PathBuf>) -> PathBuf`.
>   Unit tests: absolute XDG, relative XDG ignored, empty XDG ignored, no home.
>   `default_socket_path` uses it. Export `data_dir` from `lib.rs`. Keep `dirs`
>   for `home_dir`.
> - `crates/claude-code-acp/src/config.rs`: the same rule for
>   `claude-code-acp`, `CLAUDE_ACP_STORE_DIR` first, as a pure function with the
>   same unit tests (the bridge does not depend on `ox-protocol`).
> - Docs: `docs/architecture.md` (`oxd` socket path), `crates/oxd/src/main.rs`
>   module doc if it names the path, `crates/claude-code-acp/README.md` (table
>   row and the metadata path sentence).
> - Checks: `make check-rust`, `make smoke-claude`.
> - Check your assumptions: design entry 7.

Design entry 7 (confirmed by the user): existing macOS workspaces and sessions
in `~/Library/Application Support/ox` no longer appear; the same applies to
the bridge's store wherever `XDG_DATA_HOME` is set.

## Changes

- `crates/ox-protocol/src/client.rs`: `data_dir()` reads `XDG_DATA_HOME` and
  `dirs::home_dir()` and delegates to the pure `data_dir_from`.
  `default_socket_path()` is `$OX_SOCKET`, else `data_dir()/oxd.sock`. Four unit
  tests cover absolute XDG, relative XDG, empty or unset XDG, and no home.
- `crates/ox-protocol/src/lib.rs`: exports `data_dir`.
- `crates/claude-code-acp/src/config.rs`: the store directory comes from the
  pure `store_dir_from(store, xdg, home)`: `CLAUDE_ACP_STORE_DIR`, else
  `$XDG_DATA_HOME/claude-code-acp` when absolute, else
  `~/.local/share/claude-code-acp`, else `<temp dir>/claude-code-acp`. Five
  unit tests: the override plus the same four cases. `claude_dir` keeps its
  rule (`CLAUDE_CONFIG_DIR`, else `~/.claude`, `./.claude` without a home).
- `docs/architecture.md`: the `oxd` socket default names the XDG rule.
- `crates/claude-code-acp/README.md`: the `CLAUDE_ACP_STORE_DIR` default and
  the metadata path sentence (now `acp-sessions.json` in
  `CLAUDE_ACP_STORE_DIR`).
- `crates/oxd/src/main.rs`: unchanged; its module doc names `<socket>.db`,
  not the data path.

## Deviations

- The bridge without a home directory now uses `<temp dir>/claude-code-acp`
  for its store, where it used `./.local/share/claude-code-acp`; this is the
  design's "same rule". `claude_dir` keeps the `.` fallback, which the brief
  does not cover.
- `crates/oxctl/src/main.rs:22` still documents the socket default as
  `<data dir>/ox/oxd.sock`. The brief does not name that file, so it is
  untouched; the wording stays accurate if "data dir" is read as the XDG data
  home, and a later unit or the reviewer may want it to match
  `docs/architecture.md`.
