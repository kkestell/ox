## Contract relied on from 010

- `session.archive { session_id, discard, env }` and `session.unarchive {
  session_id, env }` answer `SessionInfo`; `Client::archive` /
  `Client::unarchive`.
- `SessionInfo.archived: bool`. An archived session is `exited`; a
  subscription (the app's `view_session`) delivers its history from `oxd`'s
  event log with no agent; `session.load` refuses it.
- Archive refuses with `UNSAVED_WORK`, whose message lists the unsaved work as
  delete's does; unarchive fails with `GIT` carrying git's message.

## Design

### Tauri commands (`crates/ox/src/lib.rs`)

- `archive_session(session_id, discard) -> Archival`, where `Archival` is
  `{type: "archived"} | {type: "unsaved_work", message}`, mapped like
  `deletion()`; `NOT_FOUND` is an error here (the session was deleted
  elsewhere), shown with `showError`.
- `unarchive_session(session_id) -> ()`; errors as strings.
- Both pass `utf8_env()`, as `delete_session` does. `ui/src/protocol.ts`
  gains `Archival` and `SessionInfo.archived`.

### Row actions

Rows now carry two actions, which makes them a group: AGENTS.md requires icon
buttons in a group to sit flush and a shared rule per kind of element. The
single `.session .close` rule becomes a `.row-actions` container, positioned
where `.close` is now (at `--row-action-inset`, centred on the row), holding
flush `icon-button`s, shown on hover or focus as `.close` is. The title's
mask covers the container's width, stated once from the button size and count
(both kinds of row have two actions). No new colours or sizes.

- Active row: **Archive Session** (`Archive` icon), then **Delete Session**
  (`X`, as now).
- Archived row: **Unarchive Session** (`ArchiveRestore`), then **Delete
  Session**.
- One in-flight set (today's `deleting`, renamed) disables both buttons of a
  row while its archive, unarchive or delete runs.

### The Archived group

Per workspace, after the active rows and only when the workspace has archived
sessions: a disclosure button "Archived" with a chevron (`ChevronRight` when
collapsed, `ChevronDown` when open) and the count, collapsed at start; its
open state lives in React state per workspace and is not saved. It takes the
session row's height, padding and hover, and the muted foreground colour the
status box uses; the chevron sits in an icon-sized box where a row's status
sits, so its text lines up with the session titles. Open, it lists the
archived rows with the same `.session` markup. The workspace's Remove button
stays disabled while any session, archived or not, exists (the daemon refuses
it).

### Archive, unarchive, delete

- `archiveSession(id, discard)`: on `unsaved_work`, the existing unsaved-work
  dialog opens with **Discard and Archive**; the dialog's state records which
  action to repeat with `discard`, so one dialog serves delete and archive.
  Archive never shows the "Branch kept" dialog (the branch is always kept).
- `unarchiveSession(id)`: errors through `showError`.
- Delete on an archived row is today's `deleteSession`.
- Selection: `select` calls `load_session` only for an exited session that
  is not archived; an archived one is only selected, and `view_session`'s
  subscription shows its history. The composer is disabled because the
  session is `exited`. A selected session that is archived stays selected.
