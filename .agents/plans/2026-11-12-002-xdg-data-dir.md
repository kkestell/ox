## Current system

- `crates/ox-protocol/src/client.rs`: `default_socket_path()` is `$OX_SOCKET`,
  else `dirs::data_dir()` (or the temp dir) joined with `ox/oxd.sock`.
- `crates/oxd/src/main.rs` keeps the database at `<socket>.db` and creates the
  socket's parent directory.
- `crates/claude-code-acp/src/config.rs`: the store is `CLAUDE_ACP_STORE_DIR`,
  else `<home>/.local/share/claude-code-acp`, ignoring `XDG_DATA_HOME`. The
  bridge does not depend on `ox-protocol`.

## Design

`ox_protocol::data_dir()` is the one lookup. It is `$XDG_DATA_HOME/ox` when
`XDG_DATA_HOME` is set to an absolute path, else `<home>/.local/share/ox`, else
`<temp dir>/ox` when there is no home, on every platform.
`default_socket_path()` is `$OX_SOCKET`, else `data_dir()/oxd.sock`. Nothing
else in Ox computes a data path. The bridge applies the same rule to
`claude-code-acp`, with `CLAUDE_ACP_STORE_DIR` still overriding. There is no
migration: the old `~/Library/Application Support/ox` is neither read nor
removed.

Both rules are built on a pure function of the environment values, so unit
tests cover them without touching the process environment.
