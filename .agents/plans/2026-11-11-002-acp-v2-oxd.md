# ACP v2, part 2: oxd

## Goal

`oxd` speaks draft ACP protocol v2 to its agents. A turn in `oxd` starts
and ends on the agent's `state_update`, whether a prompt or the agent itself
started it, and the `_ox/agent_state` extension is gone. A saved session
opens with `session/resume` and replays its conversation.

The second of three plans; `2026-11-11-001-acp-v2-claude-code-acp.md` holds the library
choices and the v2 changes that shape all three, and its compatibility
chart, `docs/acp-v2.md`, gains the `oxd` column here.

## Sequencing

Part 2 starts after part 1 lands on `main`.

## ox-protocol

- `Cargo.toml` enables `unstable_protocol_v2`.
- `src/agent.rs` and its `AgentState` and `AgentStateNotification` exports
  are removed.
- `schema` re-exports `agent_client_protocol::v2::schema`.
- `EventKind::TurnEnded` carries the v2 `StopReason`, and
  `EventKind::Update` the v2 `SessionUpdate`.

## oxd

- `session.rs` opens the connection with `Client.v2()`, initializes with
  `ProtocolVersion::V2`, and drops the `AgentStateNotification` handler.
- A saved session opens with `session/resume` and `replayFrom` start, in
  place of the `session/load` the workspaces plan uses. The replayed
  updates are recorded while the session is `Starting`, as the loaded
  conversation is today. The agent's `sessionCapabilities` is required;
  without it the session exits with an error that the agent does not
  support sessions.
- `state.rs` replaces `Turn::{Prompt, Agent}` and the
  `TurnEnded`/`AgentState` changes with one rule driven by
  `SessionUpdate::StateUpdate`:
  - A prompt makes the session `Running` at once and records
    `PromptStarted`, so a second prompt is refused as it is today.
  - `running`, `requires_action`, and an unknown state start a turn when
    none is running and record `TurnStarted`. An unknown state counts as
    working, as the spec requires.
  - `idle` ends the running turn with `TurnEnded` and its stop reason. After
    a prompt, only an `idle` that follows the agent reporting work for it
    ends the turn, since the agent may repeat an idle snapshot before it
    starts.
  - An error answer to `session/prompt` means the prompt was not inserted.
    It ends the turn with that error unless the agent has reported work for
    the prompt, in which case the turn ends at the agent's `idle`.
  - The resume snapshot sets the session's state without recording a turn
    the client did not see start.
- `awaiting_permission` still comes from the permission requests `oxd`
  holds, because `oxd` answers them.
- `ConfigOptionsSet` relies on the library dispatching a notification
  before the response that follows it. The v2 connection's ordering
  guarantee is read in the SDK documentation before keeping this, and the
  comment cites it.

## oxctl

`oxctl` names each v2 stop reason with a `match`, including `error` and its
details.

## oxd-fake-agent

The fake agent moves to `Agent.v2()`: it reports state with
`state_update`, answers prompts on insertion, echoes the user message,
replays on `session/resume`, and implements `session/close`. Each scripted
behaviour the `oxd` tests use keeps its name and meaning.

## Tests

- `state.rs` unit tests cover: a repeated idle snapshot after a prompt and
  before `running` leaves the turn running; a rejected prompt ends the turn
  with its error; a rejected prompt after `running` waits for `idle`; an
  unknown state starts a turn; the resume snapshot records no turn.
- `tests/daemon.rs` and `scripts/smoke-acp.py` read the v2 update names,
  and the saved-session tests and smoke check restore through
  `session/resume`.

## Docs

`docs/architecture.md` describes `state_update` and `session/resume` in
place of `_ox/agent_state` and `session/load`, and links to
`docs/acp-v2.md`.
