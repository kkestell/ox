### Findings

1. **Medium: `oxctl` help text describes the old socket path.**
   `crates/oxctl/src/main.rs:22`. The `--socket` doc comment, which clap shows
   in `oxctl --help`, reads `[default: $OX_SOCKET, else <data dir>/ox/oxd.sock]`.
   It was written for `dirs::data_dir()` (`~/Library/Application Support` on
   macOS). After this change `ox_protocol::data_dir()` already ends in `ox`,
   and `client.rs:84` uses `<data dir>/oxd.sock` for the same default, so the
   help now names either the abandoned macOS location or a nonexistent
   `.../ox/ox/oxd.sock`. The work log's reading ("accurate if 'data dir' is
   read as the XDG data home") conflicts with the crate's own definition of
   that term. Fix: state the default the way `docs/architecture.md:41-43`
   does, for example `[default: $OX_SOCKET, else oxd.sock in
   $XDG_DATA_HOME/ox, else ~/.local/share/ox]`.

No other place computes or describes the old path: a search of the
repository (excluding `.agents/`, `agents/`, `target/`, `node_modules/`) for
`dirs::`, `data_dir(`, `Application Support`, `data dir`, `local/share`,
`XDG_DATA` and `oxd.sock` finds only the new code, the updated docs, test
fixtures that set their own socket, and the line above. `oxd` and the app
(`crates/ox/src/lib.rs:44`) take the default from `default_socket_path()`;
`crates/oxd/src/main.rs` names only `<socket>.db`.

### Notes

- Both `data_dir_from` and `store_dir_from` match the rule: absolute
  `XDG_DATA_HOME` wins, a relative or empty one falls through (an empty
  `PathBuf` is not absolute), then `~/.local/share`, then the temp dir.
  `CLAUDE_ACP_STORE_DIR` short-circuits first. The four required cases and
  the override are asserted against exact paths; the tests are pure and touch
  no process environment.
- The rule is written twice, once per crate, as the brief requires (the
  bridge does not depend on `ox-protocol`).
- `~/.local/share/ox` need not exist on macOS; `oxd` (`main.rs:91`), the
  client (`client.rs:509`) and the bridge store (`store.rs:153`) all
  `create_dir_all` before use.

  not exercised end to end; the smoke check passes `--socket` and leaves
  `CLAUDE_ACP_STORE_DIR` and `XDG_DATA_HOME` unset. The wiring is one line
  each, so the pure-core tests are sufficient.
- `docs/architecture.md` and the bridge README omit the temp-dir fallback for
  a missing home; the code's doc comments state it.
