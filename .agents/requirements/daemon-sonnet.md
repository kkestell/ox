## Suspected defects

1. **Park timer can stop a process that just became active.** `run` selects among ops, agent events, and the park timer at random when several are ready (internal/server/session.go:60-73); on `park` it calls `stop()` without re-checking `Parkable()`. If the timer fires while an unhandled event (e.g. Claude starting a scheduled turn or an approval request) is ready, Claude can be killed mid-turn and the turn is lost. Window is tiny at 5 minutes but the design says state must not be left inconsistent.
2. **Lost resume token is never retried.** `markResumable` (internal/server/session.go:177-183) logs a store failure and returns, while the Claude agent clears `onResumable` after calling it once (internal/claude/agent.go:161-164). The session keeps an empty token, and after the next park/restart it silently starts a brand-new conversation, discarding Claude's context with no notice.
3. **Claude-reported permission modes are adopted even when not configured.** `permissionMode` (internal/claude/agent.go:174-184) adopts any mode Claude reports (e.g. `dontAsk`, `bypassPermissions`, or `manual` when a custom config lacks it), stores it and broadcasts it; `session/configure` later only validates changed fields (internal/server/methods.go:406-415), so a stored setting the UI cannot render can appear.
4. **Parked `session/configure` with no change still stores and broadcasts**, whereas a running session with no change does not (internal/server/methods.go:420-428 vs internal/claude/configure.go:52-55, methods.go:442). Inconsistent.
5. **`session/create` with an existing ID but unknown workspace reports "session_id belongs to another workspace"** (internal/server/methods.go:243-247) instead of "workspace not found".
6. **Shutdown leaves an `exited` error in transcripts.** A daemon shutdown during an active prompt records "Claude exited: signal: terminated" (internal/claude/agent.go:203-206) in history, which later reads like a Claude failure.
7. **`session/send` on a parked session blocks the session's goroutine up to one minute**, so `session/get`, `approve`, `destroy` for that session also wait (internal/server/methods.go:324-329, internal/claude/claude.go:108). The page cannot even load that session's snapshot meanwhile.
8. **A final partial request line without `\n` is dropped** (internal/server/server.go:94-100): the error branch returns before handling data read with EOF, unlike the Claude-side reader, which handles it.
9. **History growth is unbounded and `session/get` reads all of it** (internal/store/store.go:168-187, internal/server/history.go:54-72); recorded as an observation only.
10. **Stale `-32602` wording**: invalid JSON params for `session/create` report "workspace_id, harness, model, and permission_mode are required" even when the failure is a type error (internal/server/methods.go:218-220).
11. Local slash commands (e.g. `/clear`) produce no published output: only streamed top-level text deltas and a non-empty `result` are published (internal/claude/agent.go:144-165), so the user may see nothing. Unverified against live Claude.
